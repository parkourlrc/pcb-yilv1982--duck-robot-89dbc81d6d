# 自主硬件模块研发流程

> 执行层：[PCB 自动化设计到回寄上机运行手册](pcb-production-runbook.md)（需求卡 → Stage 0–10 → G1–G5 门禁 → 模板）。

日期：2026-11-05。由本项目自主HAT的设计、修订、询价及付款过程提炼；适用于有PCB、连接器和配套软件的小批模块研发。它是经验流程，不是某一家工厂永久有效的制造标准，也不代表本项目已完成首板验证。

本次案例和证据见[自主HAT复盘](references/自主扩展板阶段复盘/research.md)。自主HAT现为用户确认已付款、等待收货、线路暂停；编写本流程不恢复该线路，不产生下单、上电或监控授权。

## 1. 总体顺序

**明确需求 → 查清接口与证据 → 选架构、料号和工艺 → 原理图与封装 → 机械布局与布线 → 同源检查与导出 → 工厂核料、审核和完整报价 → 用户决定下单 → 首板验证与版本回灌。**

成本和软件支持从选型时介入；详细工厂报价仍需绑定最终生产文件。前期粗算不能冒充正式报价，后期报价暴露问题时可以回到选型或布局阶段。

本流程展开硬件工作内容，不替代本仓库[简单Spec流程](spec-process.md)：需求确认、文档确认、方案批准后才能实施；实施后的交付不自动触发Git提交或付款。既有明确授权可继续使用，只有范围、关键约束或预算处理发生变化时才重新确认相关部分。

## 2. 各阶段的工作、产物与出口

| 阶段 | 关键工作 | 最小产物 | 进入下一阶段前应明确 |
|---|---|---|---|
| 1 需求与验收 | 定义功能、使用对象、输入输出、数量、成本口径、工厂全焊或自焊、明确不做什么 | 一页需求及验收表 | 用户确认范围、预算包含项及成功标准；不要求用户自己选专业器件 |
| 2 现状与证据 | 固定参考版本；核宿主针序、观察方向、电平、机械尺寸、线束及实际系统/驱动 | 接口表、来源清单、待确认项 | 哪些是原厂规格、本机实测、上游记录或推断；关键未知有处理计划 |
| 3 架构与可采购性 | 按功能块选拓扑和精确MPN；预查库存、封装、工艺准入、软件支持；按整批采购金额排查高价料 | 方框图、电源/时钟分配、候选BOM、高价料必要性及替代方案、完整粗预算与未定费用 | 技术路径、工艺和成本没有已知硬冲突；预算偏差有明确处理决定，批准方案后实施 |
| 4 原理图与封装 | 核供电、控制、复位、保护、引脚映射、器件方向；对照原厂尺寸与脚位 | 可打开的完整工程、关键核对表 | 关键链路与符号→焊盘→物理脚位对应正确；未知额定不冒充板级能力 |
| 5 机械布局与布线 | 先固定机械与制造成本基线，再排关键回路、去耦及细脚扇出；留装配/插拔/焊接空间 | 带工艺约束的布局与布线候选、特殊工艺影响记录 | 无已知机械冲突；关键路径可实现；新增小孔、填孔等已复核整板费用，局部修改不静默破坏原有连接 |
| 6 设计检查与同源发布 | 用正确规则重铺铜、ERC/DRC/未连接/一致性检查；审生产层、BOM/CPL与装配图 | 源检查点、问题清单、同源发布包 | 硬错误处理完毕；剩余提示有解释；源、规则、报告和生产包可相互追溯 |
| 7 工厂核验与报价 | 逐组核精确料号/位号/用量/库存；核两面装配、THT、方向审核、DFM及全部费用 | 工厂匹配记录、服务范围、完整报价 | 没有漏装；工艺和价格范围明确；超预算回退或由用户明确决定例外 |
| 8 下单与配置冻结 | 用户决定下单/付款；记录订单号、源摘要、文件包及支付依据 | 订单与版本对应表、状态记录 | 下单版本唯一；不把本地新改动默认视为工厂已接收；发货/收货另记 |
| 9 首板与反馈 | 收货后按风险检查；先防烧板，再最小功能，再实际负载与系统联调 | 首板报告、实测数据、缺陷和下一版需求 | 每项功能有条件、结果和限制；通过的结论仅覆盖实测条件 |

第9阶段在本次HAT案例尚未执行。它是以后恢复研发时的安排，不是本轮要求用户立即操作。

## 3. 三项必须前移的决策

### 3.1 先算可交付成品，再算器件单价

建议统一成本口径：

`整批总价 = PCB + 元件（含备损/最低用量）+ 装配加工及服务 + 运费 + 尚未包含的税费`

加工及服务至少逐项确认工程、SMT焊盘、插件焊盘/焊接、钢网、换料、治具、特殊工艺、人工确认及包装。是否收费、何时收费以该版本订单为准，不把历史费率写成固定常数。

- 比较必须同数量、同功能、同装配范围、同服务/运费/税口径、同报价时点；无法统一的部分单列。
- 一颗芯片便宜不必然使整板便宜；它可能改变层数、封装工艺、换料、驱动适配或调试工作量。先列成本影响，再用报价验证，不预记节省。
- 库存是时点记录；商城净用量、订单备损数量、实际锁料和实物到货是不同状态。
- 拆分“器件安装面”和“通孔焊接面”。单面SMT不代表整个订单只需单面装配；底面排母、治具与后焊工序要同时纳入。
- 超预算时保留原目标、最新差额和用户决定，不能以删除配件、减少数量或漏选服务的低价称为达标。

#### 将第一版高成本教训落实为检查项

依据见[自主HAT复盘·第一版成本归因](references/自主扩展板阶段复盘/research.md)。[历史报价记录] 首轮A.1报价的主要额外支出集中在元件与PCB；[推断] 完整成本与制造约束需要更早参与方案选择。功能范围、供货时点及备损计价也影响价格，不能把所有高价都归为过度设计，也不能从不同功能版本推导同规格降本比例。

| 检查时点 | 必须回答的问题 | 留下的记录与处理规则 |
|---|---|---|
| 需求确认时 | 做几片、交付到什么装配程度、整批预算包含什么？ | 分列PCB、元件、加工服务及运税预算；注明未定费用和预留金额，不能把未知费用按零计算 |
| 关键选料时 | 哪些物料占整批金额最多，为什么需要这些规格？ | 按精确MPN的采购数量（含备损/最低用量）×单价排序，优先审查金额靠前项；记录必要指标、兼容候选、库存时点及换料/焊接影响，不只看芯片单价或元件颗数 |
| 布线前 | 满足功能的制造基线是什么，哪些局部结构会增加整板费用？ | 明确层数、铜厚、表面处理、最小孔/环宽、焊盘内孔与填孔、装配面、THT和治具；先评估关键封装扇出及热路径，再展开布线 |
| 布线中引入特殊工艺时 | 这一处小孔、填孔或新增层数的收益，是否值得整板工艺变化？ | 记录“技术必要性→可行替代→工艺变化→费用影响”；按工厂规则询价或估算后再扩展布局，不只核局部DRC |
| 详细布线前与生产包导出后 | 粗预算是否可行，最终同源报价是否仍在预算内？ | 前者采用可追溯的预估/预询价并标未知，后者绑定实际生产包重新核价；两者都包含完整装配服务，不把早期估算当最终报价 |
| 预算偏差出现时 | 超支来自必要功能、选料、工艺还是漏计服务？ | 已知超预算或存在可能改变方案的重大未定费用时，先形成保留方案、兼容替代或范围调整的取舍，按已有授权处理；超出授权再交用户决定，不带着已知冲突继续大规模布线 |

替代料仍须核实际工作条件：电容看有效容量和直流偏压、环路要求，连接器看高度、针序和载流，稳压器看电气与热条件。有货不等于便宜；品牌或价格本身也不能替代适用性判断。已确认的功能不能为降本擅自删除。

工艺降本必须落实到工程几何和制造条件，再检查、导出、重报价；不能只改下单选项，也不能把旧报价中若干收费项相加当成保证可省金额。层数与工艺由功能和制造约束共同决定，不预设所有模块都应改为两层或取消填孔。

### 3.2 机械与焊接约束先于大规模布线

先固定板框、孔位、宿主对插位置/方向/高度、插拔与线束空间；再固定功能区、关键回路和工艺空间。图纸中注明顶视/底视/插合视角，不直接等同各视角的针号。

对THT连接器同时检查两面：本体在哪面、焊点在哪面、焊接面已有何种元件、元件高度及工具/治具空间。HAT这次用过的3/5mm距离是当时特定工厂工艺筛查条件，不能推广成所有模块的统一设计规则；也不能把间距达标等同免治具。

### 3.3 软件支持与硬件选型并行

对有主控接口的模块，选芯片时就记录目标操作系统/内核、驱动是否编入、设备树、引脚复用、时钟主从、复位/使能及通信方向控制。参考工程可运行不等于本机系统直接支持。

可以先完成离线构建及配置核对，但“编译通过”“加载成功”“功能运行”“实物长期稳定”分层记录。不要等PCB付款后才首次检查关键芯片的软件可用性。

## 4. 电路与工程文件的工作方法

关键器件形成一条可检查的映射：

`需求 → 原厂资料/版本 → 精确MPN → 符号引脚 → 封装焊盘 → PCB网络 → BOM采购号 → CPL位置/角度/安装面`

- 同名器件的不同厂家、封装或后缀分别核对。不能拿另一厂家手册验证当前采购件，也不能仅凭封装外形接受替代料。
- 对电源核实际工作条件下的电流、降额、有效电容、热路径和保护边界；芯片标称电流不等于本板持续输出额定。
- 原理图/导出网表约束预期连接，PCB铜连通性另核；库名与通用商城封装名可不同，但物理映射必须有依据。
- 保留完整工程和本地依赖库；检查时加载同名工程设置、规则和库。裸PCB副本可能丢失或改变检查环境。

建议每轮修改采用：

1. 记录基线文件摘要、工具版本和需要解决的问题。
2. 在完整候选副本里修改；生成器不直接覆盖已布线主工程。
3. 对影响区域检查几何/网络，再用同规则检查全板新增问题与未连接。
4. 比较器件数量、针网、机械固定项、原有连通性和规则变化；仅在明确批准的范围内变化。
5. 保存后重新读取确认产物身份，通过后才提升为现行检查点；失败副本保留原因并退出交付入口。

自动布线和自动分析是辅助。检查失败时不能读取旧报告冒充本次结果；规则是否加载也不能只凭文件存在判断。引入或修改规则/检查工具时，做针对性的有效性验证即可，稳定后不为每次小改重复无关工具自检。

## 5. 验证按风险分层

| 层次 | 能回答的问题 | 不能替代的事情 |
|---|---|---|
| 资料与静态计算 | 原理图/脚位是否一致，工作条件与器件能力是否相容 | 实物温升、瞬态、接口兼容和工厂最终审核 |
| 原生ERC/DRC/一致性 | 当前规则下电气连接、几何与原理图同步是否存在已报告问题 | 热设计、实际信号完整性、机械装配和功能通过 |
| 有针对性的仿真/自动审查 | 模型覆盖的特定问题、可疑点与回归变化 | 工具未识别的模块或模型未覆盖的物理行为 |
| 工厂DFM/物料/装配核对 | 该生产文件与工艺/料号/装配条件是否相容 | 首板功能验收和本机系统联调 |
| 本机实测 | 在记录条件下的功能、负载、温升与异常现象 | 未测条件下的普遍可靠性 |

只对关键假设或受影响范围做有价值的检查；保持防烧板的极性、针序、电压轨及适当限流等前置核对，不机械增加大量无关软件测试。具体首板动作依据当时硬件状态与用户已授权范围决定，不能照搬旧HAT或旧IMU的操作单。

## 6. 同源交付、工厂核对与归档

一份交付包至少能定位以下内容：

- 原理图/PCB工程、必要符号封装库、规则、工具版本与源文件摘要。
- 同版本Gerber与钻孔、制造参数；人工查看铜、板框、阻焊、钢网和孔层。
- BOM：位号集合、精确MPN、厂家、采购号、单板数量及DNP状态。
- CPL：位号、坐标、旋转角、安装面；与PCB逐项对应。
- 顶底装配图、连接器/极性方向、THT/自焊/DNP工序、工厂审核未决项。
- 检查结果、已知限制、报价/订单号与文件包对应关系。

工厂库的0度方向未必等于EDA封装的0度；CPL与PCB一致仅是内部一致，仍须核对工厂装配方向。通孔阻焊开窗、DNP钢网处理、裸露焊盘及过孔工艺均要实际查看导出层。

核价时优先导出全表，并对照全部C编号/MPN、位号、数量、安装面和缺料情况。导出缺少的字段明确列为缺口，不能从30组标签推定69个位号无遗漏。图像型PDF需要放大逐段读图；预览占位图不能核角度。

用户操作外部平台时，给出短步骤及明确停点，尽量一次只取有用的一张费用/提示截图。不要反复要求截图同一已核结论，也不要根据按钮文字猜测最终费用包含项。验证码、锁屏或用户接管后尊重实际交接状态。

## 7. 状态与证据怎么记

分别记录五类状态，而非一个含糊的“完成”：

| 维度 | 例子 |
|---|---|
| 设计 | 方案已批、候选、静态检查完成、遗留项 |
| 工厂 | 文件已上传、匹配完成、审核状态、工序已确认 |
| 商务物流 | 报价、已下单、用户确认付款、已查支付回执、已发货、已收货 |
| 实物验收 | 未测、已测功能、条件/数据、失败与限制 |
| 工作安排 | 进行中、用户暂停、等待外部信息、用户明确恢复 |

证据标签沿用本项目规则：本机实测/用户确认/原厂资料/上游记录/文件核验；分析性结论用[推断]或[假设]并说明限制。页面价格称“页面实测”，不要写成硬件实测。付款与发货无自动推导关系，用户付款也不补足未做的技术验收。

每个模块维护一个现行入口、一个订单/任务状态记录和对应版本检查点。README/BOM/PROGRESS只放摘要与链接；技术数值尽量不在多处复制，变更时替换失效的现行指导。原始报告保持对应日期/源版本，旧源证据不能覆盖新源。

照片/PDF原件在可长期访问的本地位置保存；含私人信息的原件不入公开版本库，版本库留脱敏件及索引。Git提交/推送仍须用户明确要求。
