# real2sim / sim2real 工具链计划（2026-10-22 立项）

本文档是本项目自建 real2sim2real 工具链的总体规划。定位：**本机实测进得来（real2sim）、仿真产物出得去（sim2real）、真机数据回得灌（闭环迭代）**，全链不复制上游任务/训练代码/策略权重，只借鉴公开数值与许可显示资产（与 `training/README` 路线一致）。本文是计划，非完成记录；各工具落地后以对应专题文档为准。

## 二、工具链蓝图

```
[实物]                                    [仿真]                         [实物]
 标定/校准 ──> P1 real2sim 参数管线 ──> 模型生成 ──> P2 训练管线 ──> checkpoint
 (CAL/行程/    (测量→录入→注入→验证)     (duck_v0)    (任务阶梯+域随机化)      │
  称重/延迟)                                                  │
       ^                                                      v
       └────────── P4 回灌闭环 ←── 真机日志 ←── P3 sim2real 部署管线
                (摔倒/异常复现)              (观测对齐+安全分级试跑)
```

### P1 real2sim 参数管线（把手工流程工具化）

1. **trace→回填自动化**：`servo-trace` CSV + 原值法分析 → 自动产出回填表（规则：设计 ∩ 实测）→ `microduck_geometry.json` 补丁。本轮手工做通后固化为脚本。
2. **称重录入**：整机 + 大件（电池/主控/单舵机/单腿）质量录入 JSON → 按部件替换 CAD 质量并按比例缩放惯量（近似，标注假设）。
3. **零位/方向契约导出**：CAL 后 census 快照 → 自动导出「关节↔ID↔零位↔方向」单一事实表（现散在 servo-id-mapping.md 与各工具里）。
4. **时延测量**：总线往返时延脚本（写-读时间戳分布），产出命令延迟参数。
5. **模型重生成 + 一致性验证**：`build_model_v0.py` 重跑 → 自动对照（质量/惯量/关节限位/执行器逐项 diff 报告），显示层 `duck_visual` 同步挂接。

### P2 训练管线

1. **前置修复**：动作目标裁剪 ctrlrange→关节限位（README 已标 bug）；契约冻结（49 维观测/14 维动作的显式定义文档）。
2. **任务阶梯**（沿用已达标的速度命令任务）：对齐物理重训 → 域随机化版本（质量±、摩擦±、延迟、PD 增益±）→ 逐步提高迁移鲁棒性。
3. **验收双门槛**：仿真指标（速度误差/存活/推扰）+ 工作台回放目检；checkpoint 保留在本机日志目录不随库分发（现行规则）。

### P3 sim2real 部署管线

1. **路径评估**（二选一或并用，按评估定）：
   - A. robotd 补丁路线：上游真机验证、功能全（增益覆盖/审计），但补丁需按新代码移植、有已知测试失败、需适配本机 ID 映射；
   - B. 自研轻量运行时：Python/ONNX 推理 + 现有 :8765 总线 API，链路简单可控，但功能全要自建。
   评估标准：移植工作量、时延达标（50Hz 控制周期）、观测对齐难度、可调试性。
2. **观测对齐**：仿真 49 维 ↔ 实物（IMU 四元数@200 + 关节回读 + 命令）映射表 + 单元对照测试（同一姿态两侧读数一致）。
3. **安全分级试跑**（硬顺序，不可跳级）：吊起空走 → 支撑站立（手持）→ 地面原地站立 → 原地踏步 → 行走。每级配急停路径（扭矩关/总断电）与通过判据。
4. **真机日志**：试跑全程记录（关节轨迹 + IMU + 命令），既作安全审计也作 P4 原料。

### P4 回灌闭环（差异化价值）

真机异常/摔倒场景 → 日志重放到对齐后的仿真 → 复现与归因（参数差？策略缺陷？）→ 修参数或重训。这是"自己的工具链"区别于单次部署的核心：每轮真机数据都让模型更准。

## 四、边界与原则

- 全程遵守：只读参考库；借鉴公开数值显式溯源；上机操作按安全分级与断电纪律；本机实测不冒充上游结论。
- 每个工具落地即登记 `bench-tools.md` / `training/README`，验证状态如实标注（本机实测 / 上游实测 / 待确认）。
- 计划文档随阶段推进更新状态列，被推翻的路线记录原因（AGENTS 规则六）。
