## 一、缺口依据

- TI TLV320AIC3104，SLAS510G，2021-02 修订，PDF 第22页 §10.3.1：所有电源达到指定值后，RESET 必须至少拉低10ns，否则寄存器访问可能不正常。软件复位并未取消硬件复位前提。
- 同 PDF 第91页 §12 给出更稳健的上电顺序建议：IOVDD、模拟电源、DVDD，所有电源稳定前保持 RESET 低。表中部分最小间隔为0，不把图示理解为必须新增多路电源时序器。
- **勘误：原始网表/PCB的 CODEC_RST 已连接 U701.31、R308.1、C310.1；R308.2 为 +3V3，C310.2为地。** 早期“只有上拉/没有电容”的描述漏读C310，已撤回；RC名义时间常数10kΩ×100nF=1ms。原板是否满足所有电源稳定后的低脉冲，取决于实际上电斜率、门限和1.8V时序，不能仅凭RC存在判断通过，也不能宣称原板必然无法启动。新增GPIO提供明确的复位控制路径，剩余波形/驱动验证独立保留。
- TI 提到的 RESET 至 DVSS 至少1nF电容针对 ESD 复位情况；本板已有100nF，本轮未新增或删除电容。名义容量较大不等于ESD验收通过。

## 二、GPIO 与既有功能

Radxa 官方 ZERO 3 hardware-interface 页面（2026-10-31归档）标明 Pin33=GPIO3_C3，GPIO 为3.3V。板内该针原为 NC；当前已用 UART2、I2C5 和 I2S3 M0 不使用它。是否被用户实际内核的其它 overlay 占用仍需读取主控配置。

| 功能 | J101物理针号 | SoC引脚/用途 |
|---|---:|---|
| codec RESET候选 | 33 | GPIO3_C3，bank3 offset19，低有效 |
| I2S MCLK | 13 | GPIO3_A2，不能写成Pin7 |
| I2S BCLK | 12 | GPIO3_A3 |
| I2S LRCK | 35 | GPIO3_A4 |
| 主控SDO → codec DIN | 40 | GPIO3_A5 |
| 主控SDI ← codec DOUT | 38 | GPIO3_A6 |
| I2C5 SCL / SDA | 29 / 31 | GPIO3_B3 / GPIO3_B4 |

Pin33 同时有 UART5_RX/I2S1 复用功能，因此未来声卡配置必须显式使用 GPIO 模式；不能与 UART5/I2S1 overlay 同时占用。Pin3/5/27/28 在官方说明中有额外上拉与 GPIO 使用限制，本次未选用。Pin26 官方为 NC，不因本板符号给了针号就当可用 GPIO。

## 四、驱动与启动条件

已归档 Linux **v6.1参考源码**，不是用户当前内核的读取结果：

- `tlv320aic3x.c` 读取 `reset-gpios`；旧 `gpio-reset` 已弃用。驱动申请复位GPIO并输出低，在 regulator bulk enable 后延时1µs释放为高。底层使用旧整数GPIO接口，不能把其它驱动的 descriptor 逻辑电平语义照搬到这里。
- 上述1µs只是驱动启用电源后的附加延时，不代表整个低脉冲只有1µs，也不能代替引脚波形。C310=100nF会影响充放电，应核对实际GPIO驱动/引脚复用及低脉冲是否在电源稳定后满足TI要求；不从代码延时直接宣布硬件时序通过。
- 设备树需 `ti,tlv320aic3104`，以及 AVDD、IOVDD、DRVDD、DVDD 四个 supply 属性。本板前三者接3.3V，DVDD接1.8V；必须对应真实 regulator 节点。主控电源稳定后的硬复位由驱动实现，PCB接线本身不构成时序已验证。
- I2S3 M0、MCLK、全双工收放、I2C5、codec路由与静音状态需要一并配置。后续已针对历史同版本官方包补出[离线codec模块及声卡overlay](../driver-compatibility-20261031/research.md)，ABI与两种官方DTB合并检查通过；没有部署或声称开机即可播放/录音。
- 参考 v6.1 的 BMI088 accel Kconfig 依赖 SPI；BMG160 I2C 驱动有 `bmi088_gyro` I2C ID，但该版 OF 表并不覆盖完整 BMI088。不能据此判定厂商内核一定不支持：可存在 vendor 扩展或 Bosch 用户态方案。加速度计和陀螺仪需分别解决，不能仅有陀螺仪就标“IMU驱动完成”。

本轮只读 SSH 尝试使用已登记 `radxa` / `192.168.1.35`，严格主机密钥、BatchMode、5秒连接超时；终态为退出255、连接超时。`radxa-runtime-readonly.json` 为空，不作为有效运行环境证据。没有加载驱动、扫描I2C、改变GPIO或修改主控配置，未反复轮询设备。
