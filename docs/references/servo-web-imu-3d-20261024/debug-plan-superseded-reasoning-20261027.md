## 综合评估与推进顺序修订（2026-10-26 分析轮追加）

本节为同日分析轮产出（无实物操作、未连接设备）：整合当日三条工作线——本计划、[固件代码分析与 V1–V7 工作单](../imu-fw-v1-code-analysis-20261026/research.md)、[社区同类故障调研](../microduck-imu-community-20261026/research.md)——的执行顺序评估。事实与判据均来自上述已落盘记录，本节只给排序与缺口结论。

**评估结论**：方案骨架（分层归因 → 判别实验 → 单变量干预 → 回原条件验证）成立。"只有 200 缺、15 舵机全好"的形态表推理排除主机判据缺陷（BURST_IDLE/flush 丢的是尾段后缀、必伤舵机）、把嫌疑收敛到 IMU 节点段（B1 传感器任务盲区与请求拍频对撞 / B2 echo 窗口失配并列首选），是当日最有价值的一步推理。**需修订的是执行顺序**：官方 1.5.1 默认 `DBG_ENABLE=0` 的勘误已把 H1 日志降级为条件路径，而本文第 1/2 节主体仍按"有日志"编写、"本轮交付与下一步"仍把 H1 物理准备列为下一步——供板者答复日志开关之前，不应先投入 H1 近照核对与焊线工作。

**修订后的推进顺序**：

1. **发出供板者核对信息**（调研已拟稿未发）：同时解锁 H1 日志分支（构建来源、`DBG_ENABLE`、CRC 指纹 0xD9CA0DEF 对应提交）与 R31/R5 批次分支。外部依赖、零成本，最先发。
2. **V1a journal 重看**（零成本，[工作单 V1](../imu-fw-v1-code-analysis-20261026/research.md) 前半）：确认缺失形态恒为"只有 200"、孤立/成簇比例、stale 计数。
3. **V5 静止对照提前**：真机扭矩全关、同接线纯读 200 长跑。此前"10-17 轻载台架正常 vs 带载真机丢"是跨环境对比（接线/端口/软件状态均不同），不能当负载相关性证据；V5 是同条件干净版，无需新硬件。
4. **V2 间隔扫描 + V1b TELEM_CNT 序列**：独占窗口工具 10-25 已用过，无需新接线。TELEM_CNT 获取三选一需先决策：补丁加日志行重编 robotd / URT-2 旁路监听 / 台架工具配合。若走重编路线注意单变量张力——诊断构建只加日志行，两处主机修复（BURST_IDLE 2→4 ms、删 flush）另行单独验证，不与诊断混在同一变量里。
5. **H1 分支条件执行**：仅当供板者确认日志开启（或构建来源证实 `DBG_ENABLE=1`）才做近照核对 TX/GND、FT232H I2C 开关断电确认与两根日志线；确认关闭则本路径跳过，空输出不判 MCU 故障。此时第 2 节"对应从机计数"在出厂固件上不可得，判别依赖转向 V2/V3。
6. **V3 拆板单测 → V4 烧 v1 A/B**：V4 兼修复验证与本板可观测性来源（v1 统计行替代不存在的出厂日志）；前置不变——OpenOCD 全片 dump 备份、板②批次确认（R3/R4/U1 顶标对齐 0.2_10p）、MOUNT_Q 与板面焊装朝向核对。

**方向性证据备注**：0x20 CRC 错应答（IMU 收到帧但校验失败）与 0 字节超时（帧未成或被吞）两种症状并存，同向支持"请求字节在 IMU 接收路径受损/误吞"——正是 B1/B2 家族机制，V2 间隔扫描直接命中；这是现有手中最强的方向性证据，先于任何接线改动。

## 10-27 实测修订：B1/B2 退场，方向转舵机共线物理交互（用户拔舵机对照）

**用户实测（Web 界面，详见[主记录 10-27 小节](research.md#servo-unplug-ab-20261027)）**：IMU 在 HAT 第二口 + 舵机总线插原口 → 仅极少数成功（与 10-25 以来一致）；**拔掉舵机总线端子、只留 IMU → 完整数据零丢失**。上文"修订后的推进顺序"据此再次作废，以下为新顺序：

1. **分离实验 A（决定性、零硬件成本）**：舵机总线插回原口，`systemctl --user stop` servo-web 后独占脚本**只查 IMU 不查舵机**（舵机挂线静默）。高丢 ⇒ E1 静态电气负载实锤；零丢 ⇒ 需要"舵机应答流量"触发，E2/流量驱动干扰加权。
2. **向供板者发核对信息**（R31/R5 批次 + 构建来源/日志开关，拟稿在[社区调研](../microduck-imu-community-20261026/research.md)）——R31/R5 从背景问题升为直接假说核对（作者 9-30 修订针对的正是与舵机共线丢包）。
3. **临时可用配置**：IMU 接回 10-24 主链焊接分叉原走线，复测 4 分钟窗（原"下一步①"现在兼作先跑通措施；恢复 ≈100% 即第二口弃用）。
4. **journal 定量固化**（SSH 恢复后）：拔端子时刻 = 15 颗舵机应答集体消失，两窗口命中率可直接回算。
5. 原 V2 间隔扫描降级、V4 烧 v1 缓行（板②嫌疑大减）；V7 波形终审的复现条件已稳定（第二口+舵机=稳定高丢），有工具时优先。

**假说状态**：B1 出局、B2 大幅降权（单独查询时板②同样收发应答，零丢失）；板②无罪（V3 等效完成）、第二口本身无罪；新首选 E1（舵机分布电容 × IMU 支路边际，含 R5 串联电阻因素），次选 E2（固件状态机被背景流量干扰）。H1 日志路径维持条件化不变。
