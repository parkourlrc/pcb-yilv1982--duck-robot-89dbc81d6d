# IMU v0.3：7.4V 正常、两路 5V 接法失败的电气复核

日期：2026-10-31（Asia/Shanghai）。对象：本次新制 ScrapMeta 双 3P v0.3 板，STM32G031F8P6 + LSM6DSV16X + AP2210K-3.3TRG1，已刷 replica 0.2.0 飞特固件。不是旧损伤板，也不是单口 jyg9 GD32 板。本轮仅查资料和既有记录，未连接设备、改接线、上电或测量。

## 结论与勘误

1. **[厂商规格 + 原理图] 原记录“AP2210 输入上限 5.5V、7.4V 超过绝对最大值”错误，撤回。** 原厂 DS37517 Rev.4-2（March 2021）第 4 页明确 VIN/EN 推荐上限 13.2V、绝对最大值 15V；第 11 页针对 **3.3V 输出版本**的线性调整率测试覆盖 VIN=4.3–13.2V。13.2V 是芯片推荐范围，15V 是应力极限，均不能直接写成整机总线额定。
2. **[推断，条件为贴装与 BOM/原理图一致] 7.4V 经板上 LDO 生成 3.3V，是符合该器件工作范围的用法。** 不需要用“超压但暂时没坏”解释；本轮没有新板实装 U3 顶标照片、板端电压波形或温升，故不宣称全部实物与长期工况已验收。替代情况包括贴装代料、装配差异或异常瞬态，但目前没有其发生证据，不据此新增采购/改板任务。
3. **[用户确认，补充后的完整条件]** DATA/GND 在各次测试中始终接在总线上。只改变中间电源线来源：主控 pin4 时**主控启动不了**；DAPLink 5V 时**IMU PING 不通**；总线 7.4V 时正常。用户进一步确认 DAPLink 那次**只接它的 +5V，没有把 DAPLink 自身 GND 接入公共地**。两个失败不是同一种故障。
4. **[推断] DAPLink 测试缺少明确的电源负极回路，是 PING 失败的首要解释。** IMU GND 接总线，不自动等于 DAPLink GND 已接总线。除非其他 USB/调试线/设备连接恰好提供间接共地，否则正极单线不能正常供电；没有排除间接回路，因此不把“板上实际完全零电”写成实测。该次结果不能证明 5V 不兼容，也不能据此判 DAPLink 带载能力不足。
5. **[推断] pin4 失败需要单独查主控供电/启动条件。** 按既有 HAT 对插拓扑，pin4 与主控共用 5V 电源轨，已不同于 DAPLink 缺负极的情况。接 IMU 后主控无法启动，优先检查公共 5V 轨受到什么影响；欠压、启动瞬态/保护、供电线误接/接触或其他启动故障都是未验证假设。没有端点电压、电流和启动日志，不能宣称 HAT 供电不足或已短路。
6. **[厂商规格 + 推断] 设计上健康 5V 仍应可供 v0.3 工作，7.4V 也在 AP2210 推荐输入范围内。** 本次恢复同时改变了电压、电源来源及供电回路，尚未只改变电压幅度。撤回此前把“换接时 DATA/GND 被修好”列为首要解释；用户已明确这些线一直接总线。也撤回把两次失败优先合并归因于协议/软件的说法，软件异常不能用来直接解释主控无法启动。

## 供电与 DATA 分开读图

原件：[v0.3 原理图](../../schematics/imu-to-dxl-scrapmeta-v0.3/imu_to_dxl-v0.3-原理图.pdf)，单页 `imu_to_dxl_1`，图页日期 2026-09-07/09-09。[网表副本](../../schematics/imu-to-dxl-scrapmeta-v0.3/hardware-netlist.md)作交叉核对，[EDA BOM](../../schematics/imu-to-dxl-scrapmeta-v0.3/production/imu_to_dxl_v03_bom_20261025.xlsx)是 2026-10-25 导出文件。

```text
J1-2 / J3-2（VBATT）──┬── U3 VIN(1)、EN(3)
                     └── C5 10µF、C4 100nF → GND
U3 VOUT(5) → +3V3 → U2 MCU、U1 IMU、U6 缓冲器、R4 上拉、J2-1

J1-3 / J3-3（DATA）── DXL_BUS ── R6 150Ω ── DXL_DATA ── MCU PA3 RX
                         │                       ├── U6 OUTY(4)
                         ├── D1 PESD → GND        └── R4 10k → +3V3
                         └── D2 5.1V → GND
MCU PA2 TX → U6 INA(2)，PA1 → U6 OE#(1)
```

- **[原理图]** 7.4V 只送到 VBATT 前端，不直接送进 MCU、IMU 或 U6 的电源脚。J2-1 是 3.3V 轨，不是 5V/7.4V 入口。
- **[原理图]** D1/D2 保护的是 DATA，不会将 VBATT 钳成 5.1V。不能把齐纳管的 5.1V 参数当作板级电源上限。
- **[推断]** 在 3.3V 轨都正常的前提下，把 VIN 从 5V 改到 7.4V 不会把 U6 供电/上拉变为 7.4V，也不能据此解释为“总线驱动电平提升”。未排除的替代解释是原先 3.3V 轨或地参考异常。
- J1/J3 的 VBATT 并联。独立 5V 支路和总线 7.4V 不能经两个接口并接；本轮未证实此前曾发生这种接法，也不把它写成事故原因。

## 为什么 7.4V 能工作，以及实际增加的负担

**[推断]** AP2210 是线性稳压器，输入增加的电压主要变成热，输出仍为 3.3V。7.4V 在推荐范围内；因此其工作并不反常。替代边界仍为实装代料、温升/瞬态，本轮无其异常证据。

**[公式示意，不是本机实测电流/温升]** `P ≈ (VIN−3.3V) × IOUT`，完整表达还包括 `VIN × IGND`。若仅举 **IOUT=20mA** 的例子：

| 输入 | 负载项耗散 | θJA=200℃/W 时该项温升示意 |
|---|---:|---:|
| 5V | 34mW | 6.8℃ |
| 7.4V | 82mW | 16.4℃ |
| 8.4V | 102mW | 20.4℃ |

这不是数据拟合，也不是本板实际耗电。7.4V 的负载项发热约为 5V 的 2.41 倍；不等于会过热。另一方面，300mA 若在 7.4V 下连续输出，仅压差项即 1.23W，因此不能把“300mA”与“13.2V”简单组合成小封装全范围可满载指标。当前没有测到过热，不把此计算升级为改板要求。

### 用户补充原话（2026-10-31）

> 我用主控的 pin 4 做供电，5V 供电的时候主控直接启动不了；然后用 dapLink 的 5V 做供电，IMU 板 ping 不通。
>
> 这几次测试的时候 DATA 和 GND 都是连在总线上，后来我把中间的供电线也连在总线上，使用 7.4V 就正常了

针对“DAPLink 自己的 GND 是否也接到总线 GND，而不是问 IMU 的 GND”这一追问，用户回答：

> 只接了 DAPLink 的 5V

### DAPLink：两个 GND 必须属于同一回路

```text
已确认接过的线路：
DAPLink +5V ── IMU VBATT ── 板内负载 ── IMU GND ── 总线 GND
DAPLink GND ──（没有主动接到上述公共地）

独立供电所需的回路：
DAPLink +5V ── IMU VBATT
DAPLink GND ── 总线 GND ── IMU GND
总线 DATA  ── IMU DATA
```

**[推断]** 第一种接法没有明确的负极返回路径。所谓 DAPLink “5V”是相对于 **DAPLink 自己的 GND** 的电压，不能直接当成对总线 GND 的 5V。用户没有漏接 IMU 的 GND，缺的是供电源自身负极与公共地的连接。

**[假设，首要原因]** 该缺项使正常供电不能建立，能解释 PING 不通。未排除电脑 USB、SWD 地线或其他设备形成间接回路，因此不能声称原先必然完全没电、没有任何电流，亦不能据此保证补地后所有通信问题自动消失。若主控当时与同一电脑存在其他地连接，这个替代解释需要在实际拓扑中核对；本轮不要求为此重跑当前可用硬件。

### pin4：主控启动问题单独处理

**[原理图/既有拓扑]** pin4 是主控的 5V 电源轨，不是另一个隔离稳压输出；按 HAT 对插接法，IMU 从该轨取电时与主控共同使用 HAT 的 5V 支路。IMU 电源改挂 7.4V 后，IMU 负载不再由这条 5V 支路承担。HAT 本机 V1.2 与存档 V1.0 有差异；芯片名和额定不能未经核实作为本机完整供电能力。

**[推断]** 接上 IMU 就无法启动使“公共 5V 轨受影响/启动条件变化”成为优先排查方向；这仍不是欠压实测。候选包括启动阶段压降、保护/启动时序或电源接线异常，替代解释是主控其实已部分启动但访问失败。缺少现场启动状态与 5V 波形，不能唯一归因。IMU 原理图没有要求大于 5V 才启动的电路；也没有实测表明正常 IMU 负载应大到阻止主控启动，不能直接结论为“主控带不动 IMU”。

### 记录缺口与下一步

- 已纠正旧摘要的 pin4 成功窗口归属；保留原 READ/SYNC_READ 数字，但供电条件待核。此前查询活动/归档 Codex 历史未定位到该次完整操作聊天，ChatGPT 历史工具返回账户不可用；不能补造实验顺序。
- 本轮不要求改变目前正常的 7.4V 接法。若以后重试 DAPLink 5V，前提是正极和自身 GND 都正确接入；IMU VBATT 不同时接 5V 与总线 7.4V。不要把“IMU 已接总线 GND”误当作完成电源负极连接。
- 若继续查 pin4，最有区分力的是故障发生时主控公共 5V 轨是否保持正常，先与未接 IMU 时比较；若下跌，再区分负载、接线与电源启动，若不跌，再查主控启动状态。不是再做一次 PING 就能解释。
- 真正比较 v0.3 的电压适应性，应固定供电来源、DATA/GND、完整负极回路与固件，只调整 **IMU 支路**的电压；本轮没有执行此测试。
