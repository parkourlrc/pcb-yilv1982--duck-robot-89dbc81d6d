> 本文为当次源指纹对应的历史审计，后续已修事项不再列为当前故障。现行状态、澄清及完整工程对照见 [2026-10-30 复核](../audit-20261030/review.md)。旧主板无走线、TP802原点、缺TTL、内层删除等不能直接套用到现行工程。

## 结论与范围

用户要求“继续 HAT 板自主设计，先分析进展，找到解决方案”。本轮只读核对设计、运行必要的离线 ERC/DRC、核对原厂资料并修正文档；没有改原理图、PCB、生成/布线脚本，没有操作实物或下单。现有工作区改动保留，未 commit/push。

**当前处于功能电路与封装修正阶段，尚未达到布线收尾阶段。** 主板文件、布线实验文件、DRC 与生产文件不是同一状态。修复应依次为：功能电路和封装 → 确定性布局/电源地 → 布线与核对 → 同版本生产文件。实施建议见 [修复方案](../../../specs/20261028-custom-hat/recovery-plan.md)。

证据口径：下文 **[文件核对]** 表示本机文件/工具直接可复核事实，**[厂商资料]** 表示指定文档内容；两者均不是硬件实测。**[推断]** 给出依据和替代解释，**[建议]** 尚未实施。没有新增 [实测] 硬件结论。

## 2. 必须先修的电路与封装

### F01 — AP64350 用错封装，且缺散热焊盘契约

**[文件核对]** U301 是通用 8 脚连接器符号，封装却为 `PowerPAK_SO-8_Single`。PCB 实际 pad 编号为 **1、2、3、4、5、5、5、5、5**：右侧四个位置和中心大焊盘共用 pad5，全部指定为 `+5V_FB`；不存在独立的 6/7/8/9 焊盘。DSN 中 `BUCK_COMP` 只有 R304-1，没有 U301-6。

**[厂商资料]** AP64350 的 5=FB、6=COMP、7=GND、8=SW、9=EP；EP 必须电气连接 GND。见 DS41976 Rev.5-2 第 3 页。第 24 页给出专用 SO-8EP 推荐焊盘图，不能用 MOSFET 的共漏极封装代替。

**[建议]** 建立真实 9 脚符号与独立编号 1–8、EP9 的封装。核查 pad1 朝向、外围焊盘及 EP/钢网/散热过孔。厂商推荐图 EP 为 3.502×2.613 mm，外围 pad 0.802×1.505 mm，pitch 1.270 mm（按图选择旋转）；这里是复核基准，不是已完成封装。

这属于已经核实的封装映射错误，无须借助“布线容量不足”解释；装上真实 IC 后不会实现图中的正确降压连接，具体损伤结果未经实测。

### F02 — TTL 收发链和动力电源没有实现

**[文件核对]** XML 网表直接给出：

```text
UART2_TX: J101.8  — J403.1
UART2_RX: J101.10 — J403.2
DXL_DATA: J401.2  — J402.2
SERVO_VBAT: J301.7 — J401.1 — J402.1
VBATT_2S_IN: J301.1 — U301.2 / 输入阻容等
```

没有连接 UART 与 DATA 的缓冲器/三态换向电路；`SERVO_VBAT` 与 `VBATT_2S_IN` 也没有板上连接。若预期靠 J301 外部桥接，目前缺乏明确线束定义，不能宣称动力直通已经完成。

J401/J402 当前契约是 **1=VBAT、2=DATA、3=GND**。本项目既有 EH 参考约定是 **1=GND、2=VBAT、3=DATA**（见上级专题之外的 [旧 HAT 原理图核对](../../扩展板双口惯性缺答复核/research.md)）。即使保持相同 JST EH 外壳，这两套电气定义也不兼容。

**[建议]** 补齐三态发送/接收及空闲/启动状态，保持一条总线和两个插口；以已归档官方 C1/D1 逻辑拓扑为参考，逐项复核 3.3V 电平、接收隔离和回声行为。串阻/上拉/保护件按本机负载和器件规格确定，不能直接继承旧 1kΩ、150Ω、100Ω 作为已验证参数。明确单路电池入口和动力分支，保留现行 v2 方案边界，不新增外置配电采购。J301 的 1×8 通用排针不能在没有型号/额定依据时当最终大电流入口。

### F03 — BMI088 焊盘图和 I2C 契约存在错误

**[厂商资料]** Bosch BST-BMI088-DS000-19、Rev.1.9：

- 第 52 页 Table 14、第 53 页 Figure 9：**CSB2/pin5 在 I2C 模式为 DNC；PS/pin7 接 VDDIO；CSB1/pin14 接 VDDIO 或按表允许悬空。** “CSB1/CSB2 都必须拉高”的旧结论错误。
- pin10 是 SDO2 地址选择脚，接地可选 0x68，不能称为芯片第四个物理地脚。pin2 名为 NC，但表规定接地。
- 第 53 页 Figure 9：VDD/pin3 与 VDDIO/pin11 各有 100 nF 就近去耦。
- 第 55 页 Figure 11：推荐长焊盘 **0.675×0.25 mm**，并强烈建议传感器下方顶层无走线/过孔等金属结构。

**[文件核对]** 自建封装使用 0.30×0.25 mm 的短焊盘；当前 1–7 在下排从右至左、9–15 在上排从左至右，但 pin8 却在右侧、pin16 在左侧。将厂商图整体旋转为相同朝向时，应为 **8 在左、16 在右**，属于编号/几何组合不一致，不能靠整体旋转元件修复。中点坐标和 pad1 丝印标记也需要按同一视角重建。

**[建议]** 重建而非微调错误封装，独立比对顶视/底视/焊盘图；修改 CSB2 契约并加局部去耦；外侧引出短线/过孔，避开封装下方禁布建议。I2C5 本板无明确离散上拉元件，Radxa/外设已有上拉需核对，再决定本板贴装或 DNP，避免盲目叠加。

### F04 — 音频数据方向接反，录音和扬声器链未完成

**[厂商资料 + 文件核对]** Radxa 官方 40P：pin38=I2S3_SDI_M0（主控输入），pin40=I2S3_SDO_M0（主控输出）。TLV320AIC3104：pin4=DIN、pin5=DOUT（TI SLAS510G，第 5 页）。当前按同名 SDI/SDO 直连，形成输入接输入、输出接输出。

修正目标为：**Radxa 40 → codec DIN4；codec DOUT5 → Radxa 38**。I2S 时钟/主从仍需与设备树一致。此问题是文件与管脚定义核对，不是本机波形实测。

当前 U701 pin10–16（包括 MICBIAS）全为 no-connect；J504 和两颗耦合电容仅引出了耳机输出，没有麦克风输入或扬声器功放链。R04“播放与录音”尚未满足。不能用“codec 能被 I2C 扫描”代替播放/录音验收，也不能宣称已读过寄存器。

**[建议]** 保留已确认音频需求，补单路麦克风偏置/耦合/输入接口及适配目标扬声器的功放输出；立体声线路输出是否额外保留是次要布局取舍，不能因此删掉录音或基本出声。器件和阻容最终值在实施前按手册与供货锁定。

## 3. 为什么自动布线反复失败

**[文件核对]** 生成流程存在以下独立问题：

1. `build_pcb_rev_a.py` 使用手写 `net-contract.json` 赋网，另从导出 `.net` 取封装，存在两个连接事实源；它不检查原理图引脚在封装中是否真实存在，U301 错误因此一直穿过流程。
2. 脚本根据 courtyard 避让和距离评分逐件放置，不按电源热环路、QFN 扇出和去耦回路布局。固定 L301 是 12×12 mm 大封装；不能用当前摆放结果代表这个板框的容纳上限。
3. TP802 已从旧 SERVO_VBAT 改为 +5V，但不在 ANCHORS/order 中，留在板内原点 **(0,0)**，焊盘跨板边。本轮 DRC 有对应 `copper_edge_clearance`。
4. 生成器建立 F/B 地铜；`pipeline.py` 后处理会移除所有区域，仅重建 F/B 地与 B 面小块 +3V3，**不保留内层 GND 方案**。当前主板、best 文件都没有内层地平面。增加铜层数不能自动得到已连接的电源/地平面。
5. 工程 Power 类 0.6 mm、DSN 注入脚本常量 0.4 mm、生成器 0.8 mm、后处理最小值多次变化；`dsn_power_class.py` 只匹配第一个 class，可能在“第一个 class 没有 power net”时不修改后续 Power 类。当前 DSN 实际仍是 Power 0.6 mm。脚本本身还按 90 个字符截断 net 列表，存在切断网络名的潜在错误，尚未复现为当前文件故障。
6. `autoroute.py` 只检查 SES 是否存在，未强制本次返回码、导入结果与源文件指纹，不能排除旧结果复用。`pipeline.py` 每次先重建主 PCB，后续失败会使主路径停在无布线状态。主文件确已无走线；**[推断]** 覆盖来自这类重建过程，具体最后一次操作未追溯，不作定论。

**[推断]** “错误封装、按单件挤放、供电/地扇出未设计、流程状态不一致”足以解释当前工作不能收尾；尚未排除真实局部密度或机械高度限制。没有有效对照能证明“四层一定足够”或“必须六层”，也不能保证“人工点几个孔即可”。本轮不重复随机布线，因为输入电路本身已知不完整。

## 4. 载流与现行文档勘误

旧第 36 节采用 `I=0.048·ΔT^0.44·A^0.725`，A 为 mil²、ΔT=10°C，但把 2 oz 结果近似按电流翻倍，算术不符。

**[推算]** 取线宽 0.60 mm、铜厚 0.035/0.070 mm，则 A=(0.60/0.0254)·(t/0.0254)，同一公式得 **1.65 A / 2.73 A**，不是 1.64/3.3 A。这是旧经验式的复算，不是实际板载流额定；不覆盖内层窄线、过孔、连接器、温升叠加、环境或铜厚公差。

AP64350 第 22 页推荐顶底 2 oz，四层或更多层时第 2/3 层作地以改善散热；建议继续以此外层铜厚为起点，同时评估细间距制造能力。最终工艺不能由“把 DRC 下限调小”获得；HASL/ENIG、最小间距、钢网、过孔参数须与选定供应商和封装一并锁定。

### 检查命令与限制

用 KiCad 10.0.7 `sch erc --format json`、`sch export netlist --format kicadxml` 和 `pcb drc --format json --schematic-parity --refill-zones --severity-all`。报告只写到本目录，不使用 `--save-board`。本轮不重跑器件 SPICE、随机布线或硬件测试；AP64350 等效模型不能验证错误 PCB 封装、音频功能或通信成功率。

工具失败也保留记录：首次 `LIB_ID.Format()` 的 Python 绑定调用不匹配，审计脚本改用库名/元件名读取后成功；Radxa 文本打印遇到终端 GBK 不支持字符，但 UTF-8 提取文件已写成，随后直接读文件；BeautifulSoup 未安装，改用标准库提取静态表格成功。这些失败均未触碰工程源文件。

未完成：准确实物 40P 朝向/高度、EH 线束视角、2S 负载与保护额定、头壳安装干涉、音频/IMU 设备树、器件库存及生产工艺。方案可以先据图继续设计，首板发布前逐项关闭相关缺口；新 HAT 不作为旧 V1.2 共线缺答的已验证修复。
