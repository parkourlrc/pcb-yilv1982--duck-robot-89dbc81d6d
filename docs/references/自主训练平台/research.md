## 流程与输入

策略需求 → 任务与验收定义 → 环境组装 → 训练方案 → 执行训练 → 独立评估与回放 → 策略交付。需要实物使用时追加部署验证与数据回灌；评估失败回到对应环节修正。

“通用”包括统一字段格式、可组合组件和可引用资产，不要求所有策略采用相同值。

| 阶段 | 建议沉淀的通用输入 | 各策略需要定义的差异 | 向后传递的产物 |
|---|---|---|---|
| 策略需求 | 能力目标、机器人版本、使用场景、指令、约束、交付目标 | 具体能力与范围 | 需求单 |
| 任务定义 | 命令、初始状态分布、成功/失败条件、时限、验收指标 | 初始姿态、接触规则、目标阈值 | 任务说明与验收场景 |
| 环境组装 | 机器人/场景资产、观测与动作契约、执行器/传感器模型、奖励/终止/重置组件 | 观测组合、动作子集、奖励与任务状态逻辑 | 环境配置 |
| 训练方案 | 算法/网络模板、优化参数、课程、随机化、预算、种子、初始化方式 | 网络、课程与随机化范围等参数 | 训练配方 |
| 训练执行 | 需求/任务/机器人/环境/配方版本、代码与依赖快照、运行资源、可选续训检查点 | 运行编号、种子、预算 | 检查点、归一化状态、实际配置、日志 |
| 独立评估 | 策略包、匹配接口与预处理、评估场景/种子、回合数、指标定义 | 场景集合、扰动强度、合格阈值 | 评估报告与选定检查点 |
| 策略交付 | 检查点、网络与预处理定义、接口契约、目标运行端要求 | 导出格式、算子与资源约束 | 模型、哈希、配置、接口和评估报告 |
| 部署验证（扩展） | 策略包、目标机硬件/标定版本、关节映射、控制参数、动作与停止流程 | 启动姿态、动作范围与运行条件 | 实物日志与验证结果 |
| 数据回灌（扩展） | 绑定策略/设备/标定版本的时间戳日志、命令、观测、动作及失败标签 | 具体偏差与失败场景 | 参数修订或任务/训练配置新版本 |

## 优先沉淀的共享资产

1. **机器人资产包**：自建物理模型、几何/质量/惯量/碰撞/限位、执行器与传感器参数，逐项记录来源、单位、版本、验证状态；显示资产独立管理。
2. **观测与动作契约库**：语义、顺序、单位、坐标系、频率、缩放、滤波/归一化、历史窗口；区分策略输入和训练专用信息，允许多个契约版本。
3. **场景与扰动库**：地面、摩擦、初始姿态、推扰、噪声和延迟组件；训练与评估场景分别管理。
4. **任务组件与训练配方库**：奖励计算、终止/重置、命令采样、课程、算法模板；组合与数值属于策略配置。
5. **评估与产物规范**：统一指标记录、回放、失败样例、检查点与导出清单、版本来源记录；合格阈值由需求定义。

建议采用“共享资产的明确版本引用 + 本策略差异配置”；每次运行保存完整解析配置、资产哈希和代码/依赖记录。

## 复用边界

- 站立与起身可以引用同版本机器人、执行器和日志格式，但分别定义初始状态及成功/失败条件。例如站立从站姿开始、失稳摔倒为失败；起身允许躺姿开始，以起身后稳定保持为成功。此为示例，非已确认需求。
- 奖励权重、初始状态、时限、允许接触与验收阈值不作为跨策略固定常量。
- 兼容性不能只看观测维数，还需核对语义、顺序、单位、参考姿态、缩放与历史窗口。
- 归一化统计量绑定具体训练；网络权重与优化器状态不作为无条件跨策略共用资产。迁移与续训分别记录来源和兼容性。
- 硬件标定绑定具体机器人/配置版本，不混用其他设备或硬件路线的数值。
