## 1. 策略输出角度目标，不直接输出“跨一步”

V:271–273设置`JointPositionAction.scale=1.0`。所读动作实现为`q_target=HOME+raw*scale-encoder_bias`；动作层未见本项目的raw±1裁剪。底层物理关节限位、电压/力矩限制仍然存在，不可称为完全无限制。

策略在50Hz下输出14个关节目标偏移，BAM把位置误差转换为电机驱动和力矩，物理仿真产生躯干移动、足部接触与腾空。PPO根据这些后果得到的回报更新策略；不是沿物理仿真直接反向求导，也不是播放预制动作。

`scale=1.0`控制raw到角度的换算，不代表关节一定摆1rad，更不代表脚一定迈某个距离。相同scale下，输出分布、关节协同、动力学和接触不同都可能产生不同摆幅。

## 2. 直接塑造抬脚的三个信号

| 信号 | 参考配置 | 实际计算及作用 |
|---|---|---|
| 腾空时间`air_time` | 权重+3；窗口0.125–0.300s | 每步统计当前腾空时间严格落在窗口内的脚数。短促离地尚未到0.125s不得分，持续悬空超过0.300s不再得该项分数 |
| 移动时足高`foot_clearance` | 目标0.02m；基础权重−2 | 惩罚`Σ abs(足高−0.02)*足部水平速度`，移动着的脚偏离目标高度会付出代价 |
| 摆动峰值`foot_swing_height` | 目标0.02m；基础权重−0.25 | 记录每只脚离地期间最大高度，在首次落地时惩罚`Σ(峰值/0.02−1)^2` |

来源：V:330–355；证据`mjlab_velocity_rewards.py:209–323`、`mjlab_velocity_env_cfg.py:325–360`。

两个高度项都不是“越高越好”：过低和过高都会被罚。峰值项不会要求支撑脚一直悬在2cm处；它只在落地时对刚结束的一次摆动计分。腾空项也不是在落地时给一次奖励，它在满足窗口的控制步持续计分。权重是奖励率系数，不能忽略RewardManager的dt缩放，也不能仅比较权重绝对值就断言谁占主导。

这些足部项有移动命令门控：代码使用`norm(cmd_xy)+abs(cmd_yaw)>0.01`，不是只看前进速度，原地转也可激活。停步指令下不会继续用这些项要求抬脚。腾空窗口不是固定周期：没有规定另一只脚必须处于支撑相，也没有惩罚函数直接强制左右交替，不能称它保证标准交替步态。

高度测量是`left_foot/right_foot` site相对射线命中地形的竖直高度（V:243–255及`mjlab_terrain_height_sensor.py:64`），不是自动读取足底网格最低点。迁移时必须核对site位置及接触几何，不能把它直接与我们“足底几何最低点离地2mm”的诊断指标混同。

## 3. 步长没有显式目标，靠多个目标共同影响

V:342–345使线速度/角速度跟踪权重各为2，线速度核为`exp(-速度误差平方和/0.1)`；V:648–650给x±0.4m/s、y±0.3m/s、yaw±1rad/s的指令分布。目标是移动速度，不是“每步前伸5cm”。

在稳定、少滑移的直走近似下，可用平均速度≈平均每步前进距离×每秒步数理解步长与步频的耦合。该式仅为运动学解释：腾空时间不是完整一步周期，不能将0.125–0.300s直接倒数后宣称设定了步频或步长。

`foot_slip`惩罚接触脚水平速度平方和，权重−0.1（V:312–315），使贴地滑动相对付出代价。源码注释称较强滑移惩罚限制了该机器人的转向，故保留弱罚；这也意味着代码没有彻底排除拖步。速度、足高、腾空、滑移、姿态和动作变化共同决定策略找到怎样的迈步方式，无法从参数表直接推出最终步长。

低速下静止也可能得到较高速度奖励：若目标0.06m/s、其它速度误差为0，则静止时该核为`exp(-0.06²/0.1)≈0.965`（未乘权重）。这解释为什么不能只照搬速度核，必须查看足部项与其余奖励的实际贡献；不是对参考效果的否定或成功证明。

## 4. 保持姿态，同时为腿部活动留空间

腿部姿态奖励为`exp(-mean((q−HOME)^2/std^2))`，权重1；只匹配腿，不与头部命令争夺头关节。行走比站立放宽前后摆动相关关节：

| 关节 | 站立std（rad） | 行走std（rad） |
|---|---:|---:|
| 髋偏航 | 0.10 | 0.30 |
| 髋侧摆 | 0.05 | 0.05 |
| 髋前后摆 | 0.15 | 0.40 |
| 膝 | 0.15 | 0.40 |
| 踝 | 0.10 | 0.25 |

来源V:199–215、277–289及`mjlab_velocity_rewards.py:385`起。这些std是奖励容忍尺度，既不是硬角度限位，也不是要求每次摆到该角度。髋前后摆和膝被允许更多偏离HOME，髋侧摆仍较紧，表达的是“腿可以迈，但不要随意岔开”的偏好。

躯干直立奖励权重2、std²=0.05；身体横滚/俯仰角速度罚−0.05、角动量罚−0.02，此外有软关节限位和自碰撞罚。`body_pose_tracking`在主行走任务中权重为0，不能把其中的nominal_height=0.095m当成生效的身高跟踪目标。头姿态跟踪权重2，长期低头偏差另外用1秒EMA处理；这个EMA位于奖励计算，不是执行动作滤波。

## 5. 先形成步态，再逐步收紧动作与姿态

`action_rate_l2`计算raw动作相邻控制步之差的平方和，没有本项目现行平滑罚的饱和上限。课程按环境控制步计数：默认rollout24时，大致对应下表更新次数；改变rollout后不能沿用轮数标签，且实现用`common_step_counter > stage_step`判断。

| 默认更新进度附近 | 动作变化惩罚权重 |
|---|---:|
| 开始 | −0.1 |
| 500 | −0.2 |
| 750 | −0.4 |
| 1000 | −0.6 |
| 1250 | −0.8 |
| 1500 | −1.0 |

来源V:776–791、`mdp.py:3442`及`mjlab_action_rewards.py:58`。较大但缓慢的摆腿与小幅高频抖动，其逐步动作变化可以很不同；平滑罚约束变化速度，不直接指定摆幅。站立指令比例从2%逐步增加至约2000更新时25%，头部长期偏差罚从约600更新起增加，而不是一开始就全面收紧。

[上游源码记录] V:730–739称某次收紧瞬时头部姿态精度后，脚峰值由15mm降至2mm、策略停走。该记录提醒姿态精度与迈步可能冲突；未核验相应原始run数据，不能用它证明本机同样由姿态罚导致小摆幅。头部惯量、奖励相对收益等具体解释仍需对应实验。

## 6. 对本机小摆幅的启示与未解决问题

[源码核验] 本机`training/mjlab_duck/locomotion_env.py:229`奖励包含速度、转向、停止、侧移、姿态、锚点与饱和平滑等项，**没有足部腾空时间、摆动高度或接触滑移专项项**。现行动作`HOME+0.5*clip(raw,-1,1)`，执行器IdealPD25/2；参考HD1910为上述动作链及BAM。不能把全部差异归为一个scale数值。

[假设] 当前任务对“真正抬脚迈步”的正向信号不足，可能让近地挪动成为学习中容易停留的行为；窄速度核、多层奖励门控、动作高频变化、执行器响应、接触模型和训练预算等替代解释仍未排除。本机已观察到目标摆幅大于实际摆幅及约9.9Hz目标振荡，故不能仅靠加大scale或改抬脚目标认定问题已解决。

优先可借鉴的是表达目标的方式：分开定义足部高度、接触/腾空、落脚前进距离、实际速度和躯干稳定；保留固定物理参数，用分项指标判断策略是否完成一次有效迈步。若希望明确控制左右交替、步长或节奏，所查参考配方本身没有这些硬约束，需要另行设计任务目标，不能宣称照搬后自然保证。

建议先在现有轨迹能支持的范围内对齐指标；接触/腾空需真实接触数据，不用高度阈值冒充。后续若增加奖励或传感器，形成独立修改方案再实施，不能把这次调研当成新增奖励修改已批准。当前没有追加训练预算，也不以参考max_iterations=50000作为必须训练轮数。
