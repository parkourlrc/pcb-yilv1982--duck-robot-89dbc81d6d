# 本机状态估计输入核对

日期：2026-11-05。范围：从当前工程的运行代码、部署来源和本机归档中核对移动切入所需数据；本轮不连接主控、不启动服务或动作、不新增硬件测试。

后续用户补充（2026-11-05）：用户明确“这个数据有”，指原始加速度。按用户信息记录其存在；下文“当前总线包无该字段”仅为已查56/15读取路径的结论，其他获取路径与单位待第③步对齐，不据此否定用户信息。加速度接口不是第②步需求确认的必需前置，也不是当前61维策略训练的必需输入；是否作为独立速度估计器输入在第③步决定。

## 当前对象与证据边界

- **[用户确认]** 对象就是当前已装配、已运行飞特版本模型的整机；足部没有传感器。沿用M1/M2完成状态，不重新把已有装机与模型上机列为待确认。
- **[项目现状]** 当前路线为C线HD-1910-C001、kissqy HAT及新单3P IMU。旧GD32/v0.3单播适配已撤回；不能混用旧板参数。来源为根README、PROGRESS及[通信回滚记录](../飞特策略模型上机核对/restore-mixed-sync-read-20261101.md)。
- **[归档实测／源码核验]** 本轮读取11月1日/2日本机回包及固定control.47来源代码；它们支持数据字段已经存在，不等于今日在线状态或连续动作中的精度验证。11月5日M1/M2由用户确认。

## 可用性清单

| 输入 | 当前证据 | 对估计器的含义 |
|---|---|---|
| 实际关节位置 | 本机回包有`position_raw`、`position_rad`、`calibrated`；代码按`(raw-zero_raw)*2π/4096*direction`换算 | 已有读取与零位/方向处理。15舵机中策略使用14，嘴部排除；腿部运动学主要使用左右腿各5关节 |
| 实际关节速度 | `speed_raw`、`velocity_rad_s`存在；本机报告`velocity_source=hd1910_native_register_50_steps_per_second`，比例0.07669903939428206 rad/s/count | 是舵机原生速度反馈，不是动作目标差分。原生后端还调用`hd1910.delay_velocity`；诊断输出与新鲜原始速度的时间对齐需在实现时明确，不能直接假定同拍 |
| IMU角速度 | 总线块0–5字节为3轴int16；legacy代码按0.0175°/s/count解码，再转rad/s和机身坐标 | 已有3轴角速度；比例为当前软件协议解释，不是本轮独立传感器标定 |
| IMU姿态/重力方向 | 总线块6–11字节为四元数压缩分量；`ImuData`有`quat`、`gravity`、`gyro`；本机`imu_mount_verified=true` | 姿态可用于坐标变换；gravity是姿态导出的单位重力方向，不是原始加速度测量。过滤与历史值保持会影响时序 |
| 原始加速度 | 现行56/15总线包只有陀螺、四元数、计数/状态/保留位；现行`SensorReading`与`ImuData`无加速度字段 | 当前已核主控输入链没有原始线加速度，不能直接套用需要该字段的完整惯导传播方案；不据此宣称芯片没有加速度计或其他寄存器必然不可读 |
| 足部接触/压力 | 用户确认足部无传感器 | 无左右脚接触或足底力的直接测量，必须设计接触估计；不自动新增采购 |
| 舵机电流/负载 | 有`current_raw`、`load_raw`；11月1/2日本机均`current_available=false`，`current_ma=null`；标定`units_verified=false`、`current_ma_per_count=0` | 不当成已标定电流、力矩或足底力。servo-web显示的固定电流换算不覆盖此缺口 |
| 数据质量/时序 | 有每关节`feedback_fresh`、`sample_age_ms`、`missing_total`、`consecutive_missing`、`read_recovery`，以及IMU ready/sequence/status和过期统计 | 可作为估计有效性门控。它们是主机读取/缓存年龄等信息，不代表硬件同步采样时间戳；逐包采样偏差和速度延迟须处理 |

11月2日归档示例：`all_joints_fresh=true`、`sample_age_ms=5`、`imu_ready=true`，ID20的`position_rad=0.0092038847`、`speed_raw=0`、`velocity_rad_s=-0.0`，但`missing_total=331`。这说明当时读到了有效字段，也有历史缺答；不能从单帧零速推断停稳精度或长期无丢帧。

11月1日卸力运行记录目标50Hz、实际约49.97Hz；servo-web独立只读窗口约9.9Hz，两者不是同一路应用频率，也不是芯片更新率或行走期间连续有效估计频率。

## 对方案的修订

1. **已有数据**：实际关节位置/速度、姿态/角速度、零位/方向、数据质量字段，无需重新询问是否装配或是否能跑飞特模型。
2. **需要新建的计算**：用关节运动学与IMU姿态/角速度估计支撑候选及机身速度。接触估计尚未选择算法；脚相对高度、运动一致性等只能作为候选依据，不当作已测接触或保证无滑动。
3. **当前缺失的直接量**：足部接触/压力与已核主控链上的原始加速度。此前泛称“关节+IMU融合”需收窄为现有字段，不承诺完整加速度融合。先按不新增传感器、不改IMU固件的范围设计候选；若结果不足再讨论变更。
4. **关键时序问题**：飞特后端允许部分舵机沿用旧反馈；在holding分支甚至可能把缺帧关节速度置0。估计器不能只看速度数值，必须使用新鲜度/年龄/恢复状态，不能将缺答置零当成已停稳。
5. **验证边界**：在仿真中限制估计器输入与实际可用字段一致，真实接触/速度/位置仅供独立对照；不能偷偷用真实接触提高接触估计效果。输出速度及有效性供过渡控制，61维策略输入不变；5 cm仍用独立位置验收。

本轮定向检索`training`、`software/servo-web`、`software/robotd-v03`、`software/robotd-recovery`的源码/文档，未找到可直接复用的机身速度/接触估计组件；这是有限检索结果，不声称整个上游或板侧所有目录均不存在。项目已有自建运动学模型，但其参数与本机适配精度仍按环境方案边界处理。
