# 步态目标与奖励的对齐

日期：2026-11-08。范围：回应用户关于“规则化奖励与视觉、主观的正确行走姿态难以准确对应”的判断。属于方法讨论；未新增训练、未修改奖励或物理参数。此前航向罚项方案仍待确认，本次发言不视为批准该方案。

## 现有证据与解释边界

[用户观点] 当前主要困难是如何用奖励引导正确步态，而正确步态往往通过视觉和主观判断评价。

[实测，仿真] [足部奖励百轮对照](足部奖励百轮对照-20261107.md)中，20mm组在两个场景满足有效起落和交替子门槛，却有明显左右净空差异、速度不足和偏航；第三场几乎静止。组合组有腾空奖励，但没有合格迈步。数据来源为该记录及其链接的原始轨迹、逐场指标和取帧图。

[推断] 这些结果说明现有局部指标不足以代表完整目标步态；不能据此把全部训练困难归因于奖励表达。训练预算、探索、初始状态和数值响应仍是未排除因素。也不能根据本轮一个训练seed断言某种奖励普遍无效。

## 为什么局部指标与整体观感不一一对应

相同的平均速度、抬脚峰值和交替次数，可以由不同的支撑时序、脚部轨迹、关节协同和身体运动产生。几个统计量会丢失这些时序关系；分别达到目标，不保证它们组合成期望的运动。增加奖励项也会带来相互牵制，不能保证唯一收敛到人偏好的姿态。

“正确”需要分成三个层面，不应把它们全部归为审美：

| 层面 | 例子 | 建议用途 |
|---|---|---|
| 可行性和任务要求 | 不跌倒、不穿地、速度/方向正确、符合关节和执行器约束 | 物理约束、任务奖励与独立验收 |
| 时序协调 | 支撑脚稳、摆动脚前送和落地时机、左右步态关系、躯干运动与腿协调 | 按步态周期比较完整轨迹和接触时序 |
| 用户偏好 | 鸭步感、轻快或沉稳、头部/躯干摆动风格 | 用户认可的参考片段、同条件视频对比或偏好标签 |

左右不对称、滑动、过大的身体摆动等视觉问题，有一部分可被测量；哪些程度可以接受以及想要哪种风格，需要用户定义，不能由助手默认指定。

## 方法建议（尚未实现或批准）

1. 先形成可指认的目标：统一速度、视角和播放倍率，对比完整步态周期，记录“哪个更接近目标、差异在哪”。采用用户认可的正例，并保留有代表性的反例。当前20mm组可作为“大摆幅已出现但不对称和偏航”的候选，不能直接当合格专家示范。
2. 将反馈关联到轨迹：同时展示左右脚相对躯干的轨迹、接触时序、腿部角度和躯干运动。按周期/相位及速度对齐，不能拿不同速度下的视频逐帧硬对齐，或仅看单张姿态。
3. 若有同构机器人或经过适配的可信状态轨迹，可考虑参考动作跟踪/模仿目标，表达关节协同、脚部路径和支撑顺序；速度跟踪与物理可行性仍须独立约束。参考轨迹须检查关节限位、接触及执行器可实现性，不能把好看的插值动画当作可行步态。
4. 若只有视频，先作为视觉参照和标注材料；没有可靠重建、标定与适配时，不把单目视频推断的关节角度或接触当真值。积累足够且一致的片段偏好后，可研究用偏好模型表达难以手写的风格部分；本项目尚无该模型、样本量或效果证据。
5. 将验收和训练目标分开保留：主观偏好不能抵消跌倒、滑移或方向错误；客观验收通过也不自动等同于用户喜欢。视觉模型可以辅助描述和筛选，但当前未验证其对本机器人细微脚部接触、抖动与风格的判定能力，不直接作为唯一训练奖励或验收者。

以上是通用方法建议，未在本机完成模仿学习或偏好学习实验，也没有声称借用参考动作必然解决。潜在限制包括参考动作不可实现、跨机器人形态差异、偏好不一致、训练分布外表现和奖励利用。

## 如何落地这座桥：视频—状态—偏好—训练目标

本节回应用户进一步询问“如何做到这座桥”，仍是可执行的方法说明，不代表新工具或训练方案已经获批、实现。

### 1. 从可追溯的同条件片段开始

[文件核验] 本轮读取20mm组场景101的实际NPZ：`trace.npz`有1150个50Hz控制记录，包含21维qpos（根位置/四元数和14关节）、动作、目标、命令及奖励；`substeps.npz`有11500个500Hz关节前后状态、力矩、两脚净空、接触计数和接触点速度记录。来源为`gait-experiments-20261107/amplitude-20261107-gait020-s42-r1/diagnostic/straight_0.06_101/`。结合匹配的冻结MJCF，可离线重渲染姿态，无需先重训。

建议首轮从基线、20mm组和10mm＋平滑组提取相同指令与时间区间的短片，覆盖数个完整周期；20mm组的失败场景单独保留，不能只展示成功片段。它们是候选/反例，并不构成合格专家数据集。展示实际速度，不把“相同指令”误称为“实际同速”。

需要固定世界视角和地面标尺显示行进/偏航，同时提供一致比例的侧面、正面跟随视角观察腿部；保持原速，慢放仅作另一个明确标注的诊断模式。身体跟随镜头可能掩盖走不远，不能只用该镜头评审。风格比较时尽量匹配实际速度；暂不匹配的片段明确显示差异。

### 2. 在同一时间轴连接画面与状态

建议对照页同步显示：视频时间游标、左右接触条、两脚净空、髋膝踝角度、前速与偏航。脚相对躯干的前后/上下轨迹可由50Hz完整qpos做独立前向计算；当前未直接保存500Hz完整根四元数，不能把该派生轨迹声称为500Hz完整测量。接触是几何接触标志，不是测得的支撑力。

用户点击一个画面时刻，应能定位到原始run、检查点、场景、时间戳及相邻数据，而不是由视觉模型猜关节角度。时序必须按记录的控制/子步对齐，不能暗中平移数据。对有效步态可按同脚离地/落地事件提取周期，以相位坐标比较形状；周期图明确标注时间归一化，原速视频保留真实步频。没有有效周期的片段标为无合格周期，不强行制造周期。

### 3. 用户给偏好，系统提出可检验解释

首轮只需要少量比较来澄清目标，不将其当作足够训练偏好模型的样本。每次可选择“A更接近目标/B更接近目标/相近/都不接受”，附一个主要原因或圈定时间段。无需用户提供奖励权重。比较隐藏配方名字可减少先入判断，但必要的实际速度等信息不能隐藏。

| 用户描述 | 拟关联的测量 | 限制与后续验证 |
|---|---|---|
| 看起来拖脚 | 摆动期净空、接触持续情况、足端相对身体的前后路径 | 支撑脚正常接触不等于拖脚；需要结合相位 |
| 一高一低、走路歪 | 左右摆动峰值/持续时间、相位对齐后的轨迹和支撑时序 | 完美对称并非所有速度/转弯下的目标；偏航也可能来自其它因素 |
| 抬腿挺高，却没向前迈 | 落脚位置、前后摆动行程、身体净前进和接触滑速 | 脚轨迹好看不保证有有效推进，需动力学验证 |
| 身体扭得难看 | 躯干朝向/倾斜随步态相位的变化与脚部运动关系 | 有些身体摆动是平衡所需，不能默认越小越好 |
| 整体不够自然 | 用户认可的片段偏好、完整多关节时序 | 无法可靠解释时保留偏好标签，不强行编造一个数值指标 |

这些对应关系先作为解释假设，回放游标和曲线用于让用户核对“系统理解的是不是自己所指的问题”。不能根据一句“更自然”自动改权重，再把训练变化当成解释已成立。

### 4. 选择适合的训练信号，而不是把所有反馈都硬写成单帧奖励

- 能明确测量且稳定对应偏好的属性：形成目标范围或相位相关的误差项，在固定物理层的独立对照中验证；阈值以认可的步态和可行性检查为依据，不从单个较好样本武断定稿。
- 有可信、可实现参考轨迹的协调关系：考虑参考动作跟踪/模仿学习。训练比较完整周期中的关节、足端路径和接触次序，保留速度/方向任务及物理约束；参考相位、速度变化和扰动恢复如何处理仍需具体设计。
- 只能稳定判断“更喜欢哪个”、难以解释的整体风格：先用偏好作候选选择和外层调参依据；样本覆盖、一致性与独立验证具备后，再考虑训练片段偏好模型。一个常见的候选表达是`P(A优于B)=sigmoid(S(A)-S(B))`，但这是方法示意，本项目未训练该模型。片段得分如何用于PPO的奖励和信用分配需要另行设计，不能把视频总分直接逐帧重复塞入现有环境。

如果现有候选都不好，不能把“最不差”自动当作目标。应补充用户认可的参考片段或目标动作草案；人工设计动画须单独标为视觉原型，经过接触/关节/力矩可实现性核验后才能作为模仿目标。

### 5. 用未参与调参的视频检验是否真的接近目标

同等训练预算、同命令与配对初始场景比较，保留未用于偏好选择的评估场景和种子。先核对原有物理/任务门槛，再由用户盲选新旧视频；记录是否更喜欢、改善在哪、是否引入新问题。更喜欢但更容易跌倒，或客观指标更好却更不喜欢，都不算完整达标。新评价口径或新训练实现均需按项目流程确认，不能自行更改已批准验收条件。

### 第一阶段的建议交付物与现状

建议先交付离线对照页、绑定原始run/时间段的偏好记录，以及“用户描述→可测属性→拟训练信号”的映射表。首轮目标是让用户能指出并核对问题，同时形成明确的正例、反例或“尚无合格正例”结论；不承诺仅靠几次选择就能训练出自然步态。

已有：视频、冻结模型、关节/接触/速度原始记录。待做：统一多视角同步界面、用户偏好标注、认可的正例、映射验证；模仿学习和偏好模型均未实现。问答阶段未编码上述工具，也未新增训练。本节新增核验仅限本地数据字段与记录数量，未新增外部资料核验。

## 对当前计划的影响

建议优先明确目标步态和视觉反馈口径，再确定新增奖励如何服务该目标。此前[独立航向罚项提案](../../specs/20261107-步幅参数优化/航向约束下一轮提案.md)只针对直行不足，不能替代完整步态风格的定义；其待确认状态不变。本轮只记录讨论，不自动启动新配方、扩大预算或更改既有验收门槛。
