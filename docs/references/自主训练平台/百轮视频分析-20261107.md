# 第100轮训练视频分析

日期：2026-11-07。用户要求分析第100轮视频。对象是归档 `replay-100.mp4`，第100轮 rank0 策略在 `straight_0.06_101` 场景的确定性回放，23秒、10fps；它是自建物理模型的 qpos 几何回放，不是训练随机采样录像或真机视频。

## 画面与数据能说明什么

### 1. 更接近近地挪动，尚未呈现清楚的交替迈步

[画面观察] 放大后的起步、中段与末段连续帧中，双腿长期维持相近屈曲姿态，足部前后交换和明显抬脚不突出；整体有位移，不能称为静止。稳态膝关节角峰峰范围左约3.83°、右约2.37°，髋俯仰左约3.47°、右约3.28°，支持“小幅腿部运动”的描述。

[离线运动学计算] 使用原始50Hz qpos和哈希匹配的物理模型，仅调用 `mj_kinematics`，不进行动力学积分。3～23秒碰撞盒最低点离地范围：左约−1.39～0.83mm，右约−1.48～2.19mm；超过2mm的样本占比分别0%和0.1%。这说明在已保存的控制时刻，脚底几何基本贴近地面，缺少明显整脚腾空高度。负值是几何与地面重叠，不是实测地面压缩；足尖/足跟摇动时整盒最低点仍可贴地。

[推断] 这段策略更像靠小幅近地动作挪动，不能说已经形成清楚的交替支撑、摆腿步态。[假设] 可能存在滑移或利用接触振荡推进；也可能包含很低的摆脚或足部滚动。没有足底接触力、接触点切向速度及高频足部轨迹，不能确认“滑步作弊”、摩擦设置错误或某颗关节失效。

### 2. 视频低帧率会掩盖小幅快速振荡

[原始轨迹计算] 3～23秒、50Hz采样的双侧髋俯仰、膝、踝位置去均值后做FFT，最大非直流谱峰均约9.90Hz，附近9.75Hz也有明显能量；这不是精确恒频或自然步频认定。原视频仅10fps，奈奎斯特频率5Hz，无法忠实显示该约10Hz运动，可能出现看似慢动或近乎不动的混叠。

[推断] “画面看起来腿几乎不动”不能独立推出输出恒定或平滑；应结合原始50Hz关节曲线。尚未区分策略目标振荡、PD跟踪和接触求解等来源，未根据频谱推断扭矩、功耗或实物舵机风险。

### 3. 前进路线逐渐弯曲，朝向没有保持

[画面观察] 10秒后机身相对固定相机的朝向变化明显，末段侧面占比增大。[归档实测] 最大相对航向偏差约30.9°，末时刻约26.3°；目标偏航为0，验收容许10°。世界Y偏移约10秒4.9cm、15秒11.3cm、20秒19.0cm、结束25.9cm，超过5cm阈值。

[推断] 低机体系侧向速度不能保证沿最初方向直行：机器人朝向转动后，“向自己前方走”也会累积世界横向偏移。奖励主前向项与方向保持的取舍是后续线索，左右动作/接触不对称也未排除；不能仅凭此断定左腿或右腿装反。

### 4. 身体能保持，但速度不足

[归档实测/计算] 最大倾斜约6.83°，根高度约11.70～11.97cm，23秒完整回合无失败终止。说明该轨迹中姿态保持尚可，不等于步态质量或抗扰达标。

目标前速6cm/s；3～23秒原始机体系前速均值约3.92cm/s，约目标65%。既有验收前速RMSE约2.33cm/s，允许1.2cm/s；稳态沿初始方向净前进约73.6cm，要求至少96cm。最终世界X位置约82.4cm包含起步，不能与稳态净前进73.6cm混用。

### 5. 本段不能直接用“动作裁剪爆炸”解释

[归档实测] 本视频对应确定性raw动作超界率0%，最大绝对值0.644。第100轮训练随机动作约10%超界是另一统计；第1000轮确定性100%超界也不是本段状态。因此第100轮已经存在近地小幅振荡和方向漂移，不能全部归为后期std膨胀。

## 下一步建议与范围

### 同日追问：摆幅为什么小，关联哪些参数

[归档数据计算] 本轮将保存的raw动作按 `OrderedAction.process_actions` 重建目标：`q_target=clip(HOME+0.5*clip(raw,-1,1),joint_limits)`。joint_limits来自模型jnt_range，已核对安装版 `mjlab/entity/entity.py:682` 附近赋值；14维关节顺序与原模型一致。比较3～23秒各关节峰峰范围（最大值减最小值，不是单周期振幅）：

| 左髋俯仰 | 15.30° | 3.47° | 9.9Hz |
| 右髋俯仰 | 12.54° | 3.28° | 9.9Hz |
| 左膝 | 14.52° | 3.83° | 9.9Hz |
| 右膝 | 12.27° | 2.37° | 9.9Hz |
| 左踝 | 20.30° | 3.17° | 9.9Hz |
| 右踝 | 23.02° | 3.63° | 9.9Hz |

腿部10个关节目标命中关节限位裁剪的比例均为0%。目标来自确定性动作，不包含std随机噪声；实际qpos是同一20ms控制区间末端，不能把同序号差值当无延迟传递函数或精确带宽。数据和计算已追加到[分析JSON](replay100-analysis-20261107/analysis.json)及原分析脚本，未新增仿真。

[推断] 直接观察到的是“目标有更大且快速的变化，实际关节摆幅较小”。动作scale没有硬性把膝限制在2～4°，关节限位裁剪也不是这段摆幅衰减的解释；优先检查目标频率与执行响应的匹配。[假设] PD阻尼、转矩限制、惯性与支撑接触共同限制快速往返的响应。当前没有各物理子步qvel、力矩、限矩标志及接触力，不能认定某个Kp/Kd错误或已发生持续力矩饱和。

| 关联参数/设计 | 当前值与来源 | 与现象的关系及边界 |
|---|---|---|
| 动作scale、HOME、目标限位 | `locomotion_env.py`：HOME+0.5×raw；raw先限±1，再按关节范围 | scale=0.5rad即限位前HOME±28.65°，是可用范围，不保证实际摆幅。放大scale也会放大快速目标跳动；当前不存在目标限位裁剪证据 |
| PD刚度/阻尼 | `locomotion_cfg.py`：stiffness25、damping2 | 决定误差驱动与速度反馈；安装版 `actuator/pd_actuator.py` 计算Kp×位置误差+Kd×速度误差后限矩。Kp增大不保证更大有效步幅，Kd减小也可能放大振荡 |
| 力矩上限 | IdealPd `effort_limit=0.94 N·m` | 限制加速/抗负载能力；本段无原始力矩，不能根据角误差或峰峰范围确认饱和。更不能把仿真限值当本机实测连续力矩 |
| 惯性与关节摩擦 | armature0.00178、frictionloss0.0158，连杆质量/惯量沿用模型来源 | 影响快速响应和小运动阻力；未经证据不应为增大摆幅任意减质量/惯量 |
| 控制周期/策略时序 | dt0.002×decimation10=0.02s，50Hz；目标每20ms更新，无EMA平滑 | 约9.9Hz往返只有约5个控制点/周期；时序影响可跟踪性。没有独立“步频”参数，改变decimation会同时改变控制接口，不能当无成本调速 |
| 平滑奖励 | −0.05×min(mean(Δactual²)/0.01,1) | actual变量是限位后的归一化目标，不是传感到的关节位置。目标RMS变化0.05rad时达满罚；饱和后无法继续区分更剧烈目标变化。不能未经对照就称平滑罚过大/过小是唯一原因 |
| 行走奖励与足部约束 | 前速权重3，sigma=max(0.25×目标前速,0.005)；本场景sigma0.015m/s | 当前没有足部腾空时间、摆脚高度、交替支撑或接触期滑移奖励，也无步态相位信号。允许由策略自行找步态，不保证一定学出抬脚；添加抬脚奖励也不保证稳定，可能引入原地抬腿等取巧 |
| 接触参数 | 脚/地面friction=1.0/0.005/0.0001、condim3，脚geom priority1 | 决定接触运动；condim3只涉及法向及两个切向方向，后两个摩擦分量不应都当作本配置的有效调节旋钮。滑移尚未证实，先核对接触，再讨论摩擦 |
| PPO探索与学习 | std初始0.30，100轮约0.524，entropy0.005，自适应LR | 影响如何学到此策略，std不是关节摆幅命令。确定性回放不采样std，增std不能直接增大本视频步幅 |

优先级：先利用已有raw→目标→实际角比较（本轮已完成），随后如做运行诊断，再记录子步力矩/速度/触地，区分目标快速振荡与执行受限；分布稳定化、平滑项和足部奖励分别设计对照，不同时盲调scale、PD、摩擦。短FFT是描述这一段轨迹，不是独立多次实验或因果模型。安装库源码只用于参数语义核对，未重新核验原Spark依赖逐文件哈希。

首先保留第100轮为行为比较基线。后续获准重新回放时，优先记录每只脚的实际接触、接触点切向速度、50Hz关节目标与实际位置，结合50fps以上视频区分“低抬脚/滚动/滑移”和“策略目标/PD/接触振荡”。不先凭画面调摩擦、PD或硬塞步态频率。

现有分布稳定化建议仍有价值，但输出受控也不等于形成有效步态。奖励应继续按净前进、方向、平滑及脚部行为评估，不能只看站稳和总奖励。本轮没有修改训练算法、物理参数、奖励或启动训练。
