## actuator控制器的作用与STS3215/HD1910实现差异

2026-11-07，用户追问控制器用途和“sts3215与飞特”的区别。[源码核验] STS3215本身也是飞特舵机型号；这里实际比较的是B线锁定的Rhoban `STS3215Actuator`实现，与飞特公开仓库的`HD1910Actuator`实现，不能理解成两个品牌或两块外接控制板。

仿真链路：策略给出目标角度 → 控制器根据目标与反馈位置的误差计算PWM占空比/等效电压 → 电机模型结合电阻、转矩常数和转速产生力矩 → M6摩擦模型与物理引擎计算运动 → 新位置反馈。控制器模拟舵机内部位置环的响应，既不是PPO策略本身，也不是实机通信驱动。`actuator`实际选取整个执行器实现，包含电机模型和参数初始化；前文简称“选择控制器”只描述其中与本问题直接相关的一层。

| 项目 | B线Rhoban `sts3215`（62bd8ce） | 飞特公开 `hd1910`（bab3967） |
|---|---|---|
| 反馈方式 | 位置误差P控制，生成电压 | 位置误差P控制，生成电压 |
| 内部目标处理 | 有目标斜率限制，使用`q_target_smooth`和`max_velocity` | 直接使用输入目标，无这项内部目标斜率限制 |
| 占空比公式 | `clip((q_smooth-q)*P*0.166*error_gain_ratio, ±0.97)` | `clip((q_target-q)*P*0.163, ±0.97)` |
| 误差倍率 | Luwu JSON为1.3217387 | 该HD1910实现无此倍率项 |
| 本次对照的P | B线训练配置覆盖为5 | 类默认32，不能据此认定原始辨识测试或未来训练必为32 |
| 电机/摩擦数值 | 加载Luwu M6 JSON | 加载飞特公开HD1910 M6 JSON |

来源：[Rhoban控制器](feetech-c001-audit-20261107/reference-bam-feetech-actuator.py)第23–98行；[飞特控制器](feetech-c001-audit-20261107/source/bam/feetech/actuator.py)第72–94行及[父类电压控制](feetech-c001-audit-20261107/source/bam/actuator.py)第226行起；[BAM桥接](bam-gain-source-20261107/bam_mjlab.py)第613–628行。这些公式是对应源码的计算方式，不是HD-1910-C001内部固件实测公式。飞特公开仓库也有名为STS3215的类，其error_gain为0.163；因此不能把0.166当成跨版本通用常数。

Luwu将`max_velocity`设为100，来源说明称用于近似取消目标斜率限速；不能因存在平滑状态变量就认定它在当前任务中显著压小摆幅，它也不是本项目策略端EMA滤波。JSON中的kt/R等会覆盖辨识初始化值，不能认为选`sts3215`就把全部电机参数变成STS3215默认值；但控制律、基础误差换算和状态逻辑仍由这个类决定，所以也不能说字段只是名称、对响应没有影响。

[待确认] 复用该实现对本机HD-1910-C001内部控制响应的拟合精度，仍需相应辨识条件或实测依据。现有证据能确认B/C作者选择了该实现，不能确认它与C001固件完全一致，也不能确认飞特公开HD1910类在本机更准确。本项目昨天/今天原基线实际用IdealPD25/2，未加载这两个BAM控制器，故不能把现有小摆幅直接归因于`sts3215`。本轮仅解释及记录，未改参数或训练，未提交。
