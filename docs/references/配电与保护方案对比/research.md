# EH 接口与其他方案的配电/保护对照

日期：2026-10-10。用户提供 HAT 两个 SERVOS 插座局部图，询问“这个就是 et 座吧，其它方案是怎么解决这个风险的”。本轮以本地只读参考库、设计文件和已有原理图档案为主；**未测本机电流、温升、通断，未实施改线或新增采购。**

## 1. 用户图中的是什么

用户图原件已保存为[HAT SERVOS 局部图](../../photos/archive/hat-v1.2-white-20261010/hat-v1.2-servos-closeup-user-20261010.png)，与临时附件 SHA-256 一致：`fe5eee8d3c05c3ddb117850efeb02fc902b9e45c485540552d0a83d27edeafe1`。保留用户所提供的 A/B 框选，不覆盖/重画原件。

这里讨论的是 **EH**，不是 ET。存档 [HAT V1.0 原理图第 4 页](../白色扩展板原理图查证/page4.png)的两个 SERVOS 座标为 **B3B-EH-A（JST EH，3Pin）**；照片中对应这两个板端插座的位置。**外观照片不能独立确认实物品牌、端子材质、压接配线和额定电流**，V1.2 仍须核实实物。

此前“约 3A”按项目已采用的 EH 参考规格讨论，不意味着所有外形相似的国产座、所有线规都相同；3Pin 中只有一条电源正线，不能按三个针脚相加推成 9A。额定、端子和线规/温度条件要配套确认。

本轮尝试获取 JST EH 官方 PDF 和 Pollen HAT 原始 README，urllib 及 curl 均遇 TLS 握手失败；**没有成功重新核验在线厂商规格或最新官方仓库**。URL、失败记录和本地证据哈希见 [sources.json](./sources.json)。不把本轮访问失败写成“厂家资料证明”。

## 2. 两类风险应分别处理

- **正常负载超额/压降/温升**：靠足够额定的入口、铜箔、导线及分支配电处理。分支降低每支路径承载的下游电流，但不会自动均流，也不会提高某个座的额定。
- **短路/异常过载**：靠匹配的主/支路保险或电子保护切断。保护器件不能把额定不足的接头变成大电流接头；缓冲电容不等于过流保护。

## 3. C 社区方案：电池先接 dxl_hub，再分到各部位

来源：

- [社区总 README 的接线图](../../../references/microduck-community-kit/README.md)；
- [dxl_hub README](../../../references/microduck-community-kit/hardware/dxl_hub/README.md)；
- [PCB 设计源文件](../../../references/microduck-community-kit/hardware/dxl_hub/dxl_hub.kicad_pcb)、[上游布局图](../../../references/microduck-community-kit/hardware/dxl_hub/docs/1.jpg)。

上游明确画的是：

```
电池 → banana_pcb → dxl_hub
                         ├─ 头部
                         ├─ 左腿
                         ├─ 右腿
                         └─ IMU
```

**不是本会话此前简化的“电池 → HAT 单个 EH 口 → 全部 15 舵机链”。** 电池总电流首先进入配电板，再在腹部分流，不必先穿过一个舵机插头去供所有关节。

本轮直接解析 PCB 的器件/焊盘网络，结果保存为 [hub-pcb-evidence.json](./hub-pcb-evidence.json)：

- 版丝印 `dxl_hub 0.2 / 26/9/27`，J3 是独立两线通孔焊盘，**1=+BATT、2=GND**（仅适用于该 hub 设计，不是 HAT 针序）。焊盘直径 3mm、孔径 1.6mm，是设计尺寸，不由此推算合格安培数。
- 支路共用 +BATT、GND、DATA；README 说明按舵机选择接口系列，EH 用于 XL330 候选，飞特立式 A2007WV-3P、卧式 A2007WR-3P。PCB 上有重叠的替代封装（如 EH 与 A2007/PH 标称位），**八个 CN 位号不代表八个可同时装好的独立出口**；实际封装/型号依该版设计与实物核对。
- C1 标为 1000µF/10V，跨接电池与地；它用于电源缓冲方向的设计，不承担限流/熔断。10V 电容在满电与回灌瞬态下的裕量还需核验，不能因为画在板上就认定适配。
- 本 PCB 器件清单只有接口、安装焊盘和电容，**未见主/支路保险或主动过流器件**。未取得完整负载/温升、连接器额定及故障验证报告，不宣称“此板已彻底解决风险”。

[本轮配电解释图](../../photos/dxl-hub-power-distribution-explained.png)只标示该设计中的 J3/分支区和上游电力关系；不是本机接线放行，也不添加上游未画明的主控接口位置。

## 4. B 的“不打 HAT”：动力另走、分三支、另加保险

[不打 HAT 文档](../../../references/microduck-replica/docs/不打HAT.md)开头明确写“这一章是计划，还没做过”，不能当作已验证产品。

其第 3/4 步的思路是：

- 电池经开关/保险后分两大用途：一支经降压供主控，另一支原电压供舵机。
- 头、左腿、右腿在躯干分三支，明确 **V 和 G 用 18AWG 单独送往三个支路**；不让三路电流全部穿过 imu_to_dxl 板。
- 提议 5A 快熔保险、开关和 470µF 缓冲电容；FE-URT-2 的使用段强调电池原压不要误接其可能与 USB 5V 相连的 V1。

这体现“**主控/数据转换器不必承担全部舵机动力电流**”的设计方向。不是换上微雪板就自动安全，关键是动力线实际怎么走。

但其 5A、18AWG 和电容数值都是该计划的选择，不能替代本机保险协调、接头额定、线长/温升/压降、回灌和信号完整性验证；本项目继续采用“保险靠近电池出线、优先保护下游开关与线束”的原则，不照搬未验证的具体器件。不能因为文中说星形/树形可用，就忽略 1Mbps 分支长度、共地和反射/时序问题。

## 5. A/OpenRB 与官方 HAT：不能把更多端口等同于更大总电流

- [本项目 A 线 BOM 的官方资料审计](../../bom-route-a-20260928.md)记录 OpenRB-150 DYNAMIXEL 口额定**合计 3000mA**；不是每口 3A。超过板级额定仍需独立动力配电。该记录不能当作 A 教程已经实现并测过这种独立配电的证据。
- 已归档的[电池调研](../电池取电结构查证/research.md)及[硬件逆向资料](../../../references/microduck-replica/docs/硬件方案逆向.md)说明官方 HAT 从 motor connector 取电，但不提供本机 V1.2 的完整负载、线束、温升或保护结论。**不能从“官方也这样接/有人跑起来”推出全工况安全或额定可超。**

## 7. 对本项目的建议（尚未采纳为施工方案）

> **同日后续澄清**：用户要求先判断问题是否存在。[堵转核查](../舵机堵转烧板风险/research.md)发现 C001 过流保护出厂默认关闭，但未证明本机 HAT 会因短促堵转损坏。下面是额定不足时的备选方向，不是已确认必需的改造；下一步先查实际保护配置与电流路径。

保留 HAT 的主控降压和数据转换功能并不矛盾；更值得评估的是增加/设计合格的动力配电，让舵机电流不再从 HAT 一个小口进、另一个小口出：

```
电池 → 主保护 → 核准额定的配电点
                  ├─ 左腿动力
                  ├─ 右腿动力
                  ├─ 头部动力
                  └─ HAT 自身 + 主控供电（IMU 另按负载/接口安排）
HAT 的 DATA 与可靠地参考接共同总线，接口数量/接法需另定
```

这张原则图不表示现有 dxl_hub 的四组插座能额外凭空增加主控出口，也不指定哪个 CN 接哪个部位。接入 HAT/IMU 时须核对实际可用接口、电源路径、是否有重复/绕过保护的供电线和回流线，并验证支路电流、信号与机械装配。

- **不一定要装回微雪转接板或独立稳压板**；HAT 可继续承担逻辑功能，缺的是合理动力配电与保护。
- **买一个普通“一进多出”小分线板也不一定解决**：如果总输入仍是同样的小 3Pin 座，瓶颈只是搬了位置。要看总入口和整段通路的额定，不能只数口。
- 当前不能承诺“加 dxl_hub 就完全安全”；其总入口焊线、公共铜箔/过孔、各支路接头、电池保护与保险仍要验证。
- 之前单链 HAT 意向图仍是用户要求下的最小功能拓扑，保持其未放行状态；不再把它描述为社区 C 原接法。

### 社区 C 线原始连接图

`references/microduck-community-kit/README.md` 的“接线图”画出：

```text
电池 → banana_pcb → dxl_hub
                     ├─ 头部舵机支路

                     ├─ IMU 支路
                     └─ 右腿舵机支路
```

同库 `hardware/dxl_hub/README.md` 说明该板用于把电池电力分到头部、左右腿和 IMU，并合并单总线串口数据。腿内舵机按支路菊花链连接；本机现行 ID 映射是右腿 10–14、左腿 20–24。上游总图没有标出主控 HAT 如何接入 dxl_hub、也没有指定其某个 CN 口，因此不据此虚构 HAT 的端口分配。该 README 是社区硬件概念图，不能证明本机已装该 hub 或完成验收。

### 与用户描述的本机接法

用户于 2026-10-24 描述：HAT 一个 SERVOS 3P 口的 D/V/G 线接到一段 IMU 线；左右腿链各自从 ID 10、ID 20 端引出，三根对应的 D/V/G 线在 IMU 线中段去皮后分别焊在一起，IMU 线插 HAT。按当前 ID 表，右腿为 10→11→12→13→14，左腿为 20→21→22→23→24；IMU ID 200 是同一外部焊点上的支路。

这是一处外部焊接的总线分叉：D 共用总线信号，V/G 在分叉处分配电源/回流。两腿的供电不会穿过 IMU PCB；但从 HAT 3P 口到分叉点的 V/G 共用线以及 HAT 接口承载两腿电流之和，分叉后的腿支路各自承载对应腿负载。实际电流、线规、插接端额定和焊点质量本轮均未知，不能据此断言合格或不合格。

与社区 C 方案的区别是动力入口和分配位置：社区图将电池先送到 dxl_hub 再分到部位支路；用户描述的是从 HAT 单个 3P 口经一段公共线后才焊接分叉。该拓扑比较不自动触发新增 hub、改线或采购；需要按项目已确认的“先按现路线、遇实测问题再调整”处理。电池进入 HAT 的具体端口/焊盘和头部支路不在本轮描述内，均待按实物记录核对。另一个 B 线“不打 HAT”文档也画了 TTL 口分头颈、左右腿三路、IMU 200 挂任一路的计划，但其原文声明未实施；它不是 C 线社区 dxl_hub 图，也不是本机现行施工依据，具体见只读参考 [`不打HAT.md`](../../../references/microduck-replica/docs/不打HAT.md) 第 3–4 步。
