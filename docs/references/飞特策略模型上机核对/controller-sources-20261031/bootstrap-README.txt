Microduck 2026.10.3101：兼容旧卡一次性安装软件更新入口

已有“设置 → 软件更新”入口的27版用户直接网页更新，不要重复运行本引导。
本包不是镜像，也不是网页上传包；网页上传使用 2026.10.3101.software-update.tar。
包含同版签名软件包、公开安装器、已验证 ARM64 升级引擎、发行公钥、Vosk 中文
模型和 linux-aarch64/cp313 依赖，不包含发行私钥或个人 API Key／标定／配对信息。

首次安装由维护者通过 SSH 完成：
1. 对照发布页核验压缩包 SHA256，核对 files.json 每个文件的大小和哈希，拒绝链接和越界路径。
2. 确认 HD1910 飞特系统、radxa 账号、Python 3.13 和服务／目录布局受支持，备份个人配置。
3. 停止策略、语音、音乐及录放／舵机／标定会话，按原准备检查保持安全停止状态。
   设备不全而旧准备检查不能通过时，先由维护者处理，不强行站立或伪造检查。
4. 核验 resources/resources-manifest.json 中的304个资源文件。
   /opt/microduck/resources 不存在时才按 root 属主、目录755／文件644布置；
   已存在时先核对清单一致，不混合覆盖，并核对系统和资源兼容性。
5. 在解压目录执行：

sudo python3 software/updater/bootstrap.py --package 2026.10.3101.software-update.tar --public-key software/updater/release.pub --engine updaterd

实机不添加 --offline，不伪造预检。安装器验证签名、检查状态、备份原服务、
迁移允许的用户状态并验证新服务；第一阶段不替换 robotd／padd／模型／内核／引导。
6. 网页恢复后核对软件版本，再按设置页提示扶稳、卸力并明确确认配套驱动更新。
   等组件和真实运行进程检查通过，再学习手柄映射；不要只按 robotd 的 .47 版本判断完成。

两阶段失败时各自恢复；新映射运行后，回退不兼容的旧软件之前先恢复匹配的旧配套驱动。
保持用户配置和保护记录。未知二进制、自定义服务布局和未通过的准备检查不强制覆盖。
本次自动化和实物验收范围以 runtime-provenance.json 为准。

本修订配套原生程序与2026.10.31相同；不重复安装已由页面实际核验确认完成的组件。
