# HAT 设计流程改进建议

- 日期：2026-10-30。
- 状态：2026-10-30 用户授权先核真伪、清理文档，再实施流程改进。阶段 1–3 沿用既有功能/修复范围；本轮实施范围限定为复核后 P01–P06，不修改电路、布局、布线或制造规则。
- 用户约束：由主会话执行，不使用 subagent；已有功能范围继续有效。
- 依据：[修复方案](recovery-plan.md)、[历史审计](../../references/hat-simulation-tools-20261029/audit-20261029/review.md)、[本轮工具及失败记录](../../references/kicad-agent-skills-20261030/research.md)。下列为建议，不是已实现能力。

## 1. 先固定输入与检查条件

保留一份主工程。每轮从主工程建立带编号的完整工作副本，包含 PCB、原理图及子页、工程设置、自定义规则、库表和本地库。开始时记录源文件摘要、KiCad 版本及检查命令；不得只复制 PCB 后使用默认规则比较 DRC。

原理图及其导出网表作为网络连接唯一事实源；net-contract 只表达期望并用于核对。同步检查位号、库标识、引脚编号、NC/DNP、封装焊盘和网络对应关系，不直接照搬占位连接器符号代表真实 IC。

## 2. 分阶段完成，按条件进入下一阶段

| 阶段 | 工作 | 进入下一阶段的条件 |
|---|---|---|
| 电路与封装 | 逐功能核对供电、TTL、IMU、ToF、播放/录音，核实真实引脚和焊盘图 | 功能路径齐全；关键连接及极性有来源；无已知错误封装 |
| 机械与布局 | 先排孔位/40P/接口及插拔空间，再按电源、音频、IMU 回路成组摆放 | 无器件机械冲突；明确正反面/高度；关键去耦、热环路及扇出可实现 |
| 关键布线 | 先处理电源地、反馈、局部去耦与细脚扇出，维护参考平面 | 局部连接正确；没有新增短路、间距及 keepout 问题 |
| 普通信号 | 在关键布线约束下布剩余网络；自动布线只作为候选生成 | 未连接收敛；不通过删除连接/放宽规则隐藏问题 |
| 发布检查 | 同规则重铺铜，ERC/DRC、原理图与板一致性、二维/三维及生产输出核查 | 严重错误和未连接清零，剩余提示逐项有合理解释，生产文件与源版本一致 |

布局阶段允许未连接；不要求早期每一步全板 DRC 清零。但每个接受的修改必须解决明确问题，且新增连接断开等影响有清单和后续处理安排，不能只凭总数减少接受。

## 3. 局部修改必须依据几何和连接关系

先查看实际铜层、焊盘、过孔、keepout 和周边器件，再生成候选。移动带线器件时同时处理连接到它的旧走线；依据真实焊盘层和编号引出，不能按旧坐标盲接。临时放置改变后先重铺铜，避免缓存铜区与新器件碰撞造成比较混乱。

本轮曾直接试探 J506 坐标、给焊盘直接加过孔、按坐标补 I2S_SDO，产生新短路和机械冲突。后续停止这种缺少几何约束的坐标枚举；DRC 应用于验证已设计的路径，而非替代路径设计。候选失败及时归因并保留报告，不让失败的候选成为现行版。

## 4. 检查与保存形成闭合流程

每轮执行：读取及源指纹 → 完整副本 → 一个明确问题组的修改 → 固定规则重铺铜/检查 → 对照基线审阅 → 保存可追溯检查点。成功后的检查点可以仍未布完，但必须明确其未完成项；失败不覆盖主文件。

CLI/路由进程的返回码、导出成功标志、文件是否本次生成、报告的源指纹必须检查。脚本失败后禁止读取旧报告输出“0 错误”。DRC JSON 的 violations、unconnected_items、schematic_parity 分别统计；pcbnew 的 tracks 集合包含过孔时必须拆开统计。此前 612 是 538 条走线段加 74 个过孔，不能写作 612 条走线另加 74 孔。

工艺规则预先确定并保持统一；不按路由器结果降低间距/线宽要求。普通 DRC 与重铺铜、是否含原理图一致性检查的结果必须注明条件，不能把不同规则/命令的计数直接解释为改进或退步。

## 5. 工具与交付边界

使用本机已确认的 kicad-cli 做网表/检查/导出，pcbnew 或 GUI 做必要修改；当前 Seeed MCP 用于其已核验的分析、验证和导出能力。不把换工具当作电路设计完成，也不因缺乏完整 SPICE 模型持续阻塞已可依据厂商电路推进的工作；模型覆盖与实物待验证项明确记录。

通过发布检查后，从同一版本一次导出 Gerber、钻孔、BOM、CPL、DNP 和装配资料，并写清来源摘要。生产文件导出、下单和实物功能验收分别记录；默认不 commit/push、不下单、不上电。

## 本轮实施范围

依据[问题真实性复核](../../references/hat-simulation-tools-20261029/audit-20261030/review.md)：使用完整工程副本生成带指纹的 ERC/DRC/网表报告；替换默认破坏式 pipeline；自动路由仅接受显式工作副本并验证本次返回码/输出；停止旧生成器默认赋网/覆盖。源码和规则保持不变，没有自动回写主工程或自动下单。

验收：真实主板副本得到可比的 29/23/101 基线；源文件摘要不变；故意指定不存在的 CLI 时明确失败且不产生通过报告；拒绝对主工程直接自动布线。设计缺陷仍作为后续任务，不计作流程验收失败。

## 后续设计顺序

1. 修正主工程/候选/报告的关联与统计，保留完整项目规则和来源摘要。
2. 修正 pipeline 的先覆盖后验证行为，建立失败即停、通过后保留检查点的流程。
3. 后续设计修复先处理 J301/J506 与音频区、U501 周边去耦与扇出，再继续普通信号布线；本轮只完成流程，不改设计。

## 实施与验收（2026-10-30）

- pipeline、autoroute 已改为完整副本及独立报告流程；旧 build/DSN 改写器命令行入口停用，保留历史代码。没有自动重建、补孔、规则放宽或回写主板。
- 流程验收当时的源基线：29违规、23未连接、101一致性项，ERC=0；32个NC表示差异单列后，实际导出网表与PCB/契约核对无其他引脚网络分配差异。这不代表板上铜连接正确。后续[U501修复](../../references/hat-simulation-tools-20261029/u501-repair-20261030/research.md)已将主板违规降至24，旧验收记录不覆盖。
- [验收证据](../../references/hat-simulation-tools-20261029/audit-20261030/workflow-verification.json)：完整工程基线、缺CLI、主工程路由拒绝、旧入口拒绝、现存错误阻止路由、旧SES拒绝、进程失败和无输出拒绝均通过；源设计摘要未变。
- 未验证成功自动布线/SES导入路径、制造性或硬件功能；不把失败路径检查当整套自动布线验收。
- 修改保留工作区，未提交/推送。
