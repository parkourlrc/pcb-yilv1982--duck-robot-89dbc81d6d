## 拟定行为

### 点击与入场

- Studio 添加独立“躺姿起身”按钮和状态说明，保持 LB/RB 左右踢球绑定；不把起身塞进普通技能列表。
- 新增原生 RPC `robot.recover {}`，仅显式点击产生一次请求并返回本次 `request_id`；同一路由用 `action=keepalive/cancel` 和匹配的 request_id 续期／取消，默认 action=start。原生同时校验：motion/control、walk 模型与执行文件匹配、policy 当前关闭、没有 HOME 插值／技能／模型切换／调试接管／关机，传感器完整且新鲜、IMU 安装方向已验证、确认为倒地。不能仅靠网页置灰保证条件。
- 入场复用原生倒地判定和 80 ms 新鲜度边界，并在控制线程重新检查当拍传感器；软件与硬件扭矩状态不一致或未知时拒绝，不猜测上力状态。
- 已卸力时，复用现有后端“预载实测当前位置→上力→回读确认”的流程，再读取新的关节和 IMU 数据后才第一次推理；已确认上力时使用当拍位置开始。保留 generation 取消屏障，旧请求不能跨卸力／重启重新生效。
- 从真实关节姿态构造第一帧；清除旧技能与旧速度，模型 last_action 按已有 reset 规则清零，目标滤波的历史值从实测位置初始化，不能在第一帧隐式跳回 HOME。

### 恢复与保持

- 强制使用已加载的 `Net::Walk` 联合模型，全部速度／头／身体命令中性，原样应用 scale=1.0、头滤波0.5、腿滤波0.7和现有增益／限位。
- 原生设独立状态 `idle → starting → recovering → recovered_hold`，记录请求编号、开始时间、失败原因和传感器判据。客户端的 HTTP 成功只代表请求接收，状态以控制线程回报为准。
- 恢复期间原生拒绝其他非中性动作，网页同步禁止摇杆、起坐和技能。卸力、停止及原生故障／关机取消优先；停止或 HOME 请求在恢复中先取消并卸力，不从未恢复的姿态自动拉 HOME。要重新执行 HOME 须在恢复取消完成后重新明确请求。
- 拟定本项目首轮时间上限为 **8 秒**，从首次策略输出起计；这是参照训练倒地终止时长选择的实验上限，**不是已验证的真机安全时长**。不成功则取消策略、原生卸力并回读；不得反复重试或在失败后强回 HOME。
- 姿态恢复判据复用当前实测 HOME 的 **关节误差≤5°（不计嘴）、倾角≤10°**，并要求新鲜有效数据连续 **1 秒**。1秒为本项目拟定防瞬时误判窗口；有效数据中断即重新计时。判据偏严可能把实际已直立但关节未接近 HOME 判为未完成，首测必须记录误差，不能因此偷偷放宽。
- 达到判据后进入 `recovered_hold`，继续同一模型、零速度保持；页面显示“姿态已恢复，零速度保持”。模型仍可能做平衡调整，不能承诺关节静止或据此宣布已稳定承重。用户点“开始走”才退出恢复输入限制，并再次校验普通起步条件、清空旧输入；模型不重置跳姿。用户点“停止／卸力”执行原生卸力。
- 若 `recovered_hold` 再次失去直立判据持续1秒，取消并卸力，不自动开启另一轮恢复。保护或无效传感器优先于此延时。
- 恢复运行期间发生无效／缺失关键传感器、非有限模型输出或既有保护触发，停止本次输出并取消／请求原生卸力；回读无法确认时明确显示“卸力未确认”，不伪报已安全。空格／Select 原生卸力保留。
- 页面离开、控制会话失效或连接断开时取消本次恢复及恢复保持；复用已有会话取消通路，并补齐原生有限期租约，不能只依赖 JS 收尾消息。已核对现有网页摇杆为100 ms发送、原生速度deadman为500 ms；现有6秒网页方向盘租约、2秒/6秒watch机制并不停止策略。新增恢复keepalive沿用100 ms／500 ms这组节拍：只由仍在该页面的当前控制会话触发，Studio验证所有权后转发，不在后台无条件续期。原生校验request_id和单调序号，过期或旧序号不能续期／重新上力；卸力不限所有者。新租约仅覆盖恢复和恢复保持，不改变普通驾驶。

## 必要验证与验收边界

- 协议解析和状态机覆盖：无效／过期反馈拒绝；上力后必须重读；重复请求不重置计时；卸力／旧租约／切模式取消优先；超时卸力；连续判据、恢复保持及再次倒地退出。使用假 IO，不占用真机串口。
- 同一传感器序列下核对恢复确实选择 Net::Walk，scale/滤波与正常 walk 一致；入场滤波历史为实测位置，普通起步保护仍有效。
- Studio 后端检查躺姿新入口、旧动作拦截、状态显示、断连／会话失效取消和紧急卸力；不编写只复述按钮文字的低价值测试。
- 构建 ARM64 robotd，检查配套 Python/JS 可解析。部署后的验收仅只读：两服务 active/enabled、六模型与标定不变、动态策略关闭、启动卸力已确认、新能力可见。不能用读接口通过代替动作成功。
- 实物动作验收单独记录起始躺姿、支撑条件、是否实际承重站稳、动作耗时、退出原因及推理周期；首次不做连续三次、不同姿态或自动重试。IMU不能独立判断脚底接触，需用户观察。
