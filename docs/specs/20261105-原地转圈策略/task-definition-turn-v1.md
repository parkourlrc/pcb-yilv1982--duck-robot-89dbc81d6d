## 新增移动切入流程（边界已确认，参数待定）

用户纠正先前“静止和移动两种初态”的说法：目标是移动中收到转圈请求后平滑切换，而非在持续平移状态下执行原地转圈。允许仍从静止站姿直接起转。

建议流程：

1. **行走减速**：由行走控制逐渐将平移速度命令降至0，暂不启动非零转圈命令。收到请求时记录过渡起点，用于统计减速时间和距离；实际停车能力待仿真验证，不能把命令归零等同于实际停稳。
2. **停稳交接**：确认实际水平速度、倾斜和姿态变化在待定阈值内持续待定窗口后，记录躯干XY作为固定转圈锚点。策略交接从零转速开始，再按已定斜率升至请求转速。锚点在转圈策略接管前建立，交接与起转漂移也计入5 cm，不在接管后再次置零。静止入口也需满足停稳条件；不要求人为等待或把关节硬拉回HOME。
3. **原地转圈**：执行已确认的左右/停止/换向命令；从上述锚点开始的全过程最大水平漂移≤5 cm，后续换向、停止不重置锚点。

过渡期间不重置物理状态来伪装停稳，也不强制瞬间切换关节目标。相同61维输入仅说明字段布局一致；两策略的HOME、动作缩放、原始动作历史、归一化和输出目标交接须单独设计与验证。不能默认直接复制上一模型动作值或线性混合输出即平滑。

职责划分建议（2026-11-05，用户问答，未批准具体实现）：过渡由代码状态机调度，模型产生维持平衡的关节动作。代码负责接收请求、渐变速度命令、停稳门控、记录锚点、切换策略、超时及异常处理；先由walk执行减速与零速保持，停稳后交给转圈模型从零转速起转。walk减速性能须实测/仿真验证，不因有零速命令就视为可用；若不满足需另定适配或训练范围。转圈训练应覆盖真实交接附近的站姿、关节速度和小残余运动，不能仅训练精确HOME并假定能接管。策略切换时动作目标/HOME/缩放/归一化/动作历史处理属于第③步具体方案，不能随意插值两模型输出后宣称平滑。

另一候选是同一模型训练平移到转圈的全过程，代码只连续调命令并监控验收；这会把当前专门转圈任务扩大为联合行走/转圈任务。现阶段建议先用walk减速+转圈模型接管，不默认新增第三个“过渡模型”，也不将建议写成已批准实现。无论路线如何，都需在仿真中连续执行完整过渡验收，不reset物理状态，命令平滑不代替实际运动平滑。

待定项：允许切入的行走方向/速度范围；减速命令斜率、完成时限及允许距离；停稳速度/姿态阈值与保持窗口；策略交接时限与目标变化指标；超时/失稳的失败及停止处理。用户已确认采用下述独立速度估计组件；仿真真实速度用于独立核验，不能直接将仿真真值当成实物已有输入。

过渡段需单独记录从收到请求开始的时间、路径长度与相对过渡起点的最大水平位移；最终使用哪些指标及其阈值待确定。转圈锚点独立记录，过渡位移不纳入5 cm判据，但不能因此省略过渡验收。新增评估需覆盖不同入口速度/方向/步态时刻到左转和右转，以及无法停稳的失败情况；具体场景待补。原24回合保留，不代表新入口已经验证。

### 入口移动速度如何确定（方法建议，尚未采集）

“入口速度”指收到转圈切换请求时的实际水平移动速度，不是转圈策略接管时的速度；后者应已符合待定停稳条件。分别记录当时行走命令、躯干原点实际世界XY速度及当前朝向下的前后/侧向分量，并记录偏航角速度。水平速率为 `sqrt(vx_world^2+vy_world^2)`；单一速率不能区分前进、后退、侧移或边走边转。

建议先确定需要覆盖的移动方向，再在与walk合同匹配的仿真配置中让行走模型实际运行，以少量由低到高的速度命令观察可持续行走状态，记录命令和实际速度。必须使用有正常步态的行走状态切入，不能仅给HOME静止机器人赋予根部速度来冒充移动切换。模型/环境尚未适配或不能稳定行走时，应报告前置条件未完成，不能据合同命令上限填写已验证入口速度。

依据已观察到的可持续行走范围选低/中/高档和边界点作为过渡候选工况，在不同步态时刻触发切换。记录触发瞬时速度，以及明确窗口下的触发前速度统计；窗口长度和汇总方式需冻结，避免用均值掩盖步态中的峰值。最终支持范围以相应减速/停稳/交接及后续转圈评估通过为依据，未通过档位不进入“已验证”选项；有限测试点不表述为连续区间内所有速度均已保证。

平台字段建议为“入口方向/运动类型选择 + 经验证速度档位选择”，自动带入证据、模型版本和条件。尚无结果时仅提供带待验证标签的参考档位，不要求用户猜一个实物速度。首轮可建议从直线前进覆盖起，再决定是否增加后退/侧移/边走边转；此范围尚未获用户确认。实物速度估计采用下述已确认方向，具体反馈质量和接触判断仍待核实；不能以摇杆值或速度命令替代实测速率，也不因此扩充已定61维actor输入。

### 独立速度估计组件（方向已确认，2026-11-05）

阶段边界澄清（2026-11-05）：用户说明原始加速度数据有，并追问其与训练及第②步的关系。记录为用户提供的信息，具体获取接口与单位留到第③步核对；此前已查56/15总线包不含该字段只限定该读取路径，不能扩大为整机无此数据。第②步负责定义移动切入、减速/停稳和漂移验收目标，不以加速度接口或估计器实现作为需求讨论前置。第③步确定估计器是否使用加速度、如何取得及仿真如何匹配；61维策略观测保持原约定，不因数据存在自动加入加速度。仿真奖励/验收可用真实速度/位置，原始加速度不是其必需输入。此前“下一项核对反馈”属于提前核对第③步依赖，不是新增第②步必经关卡。

用户以“ok”确认上一轮建议：用实际关节角/速度、IMU和足部接触判断进行机身速度估计，作为独立组件供入口速度分档与停稳门控；61维策略输入保持不变。先在仿真中对照真实速度验证误差和延迟，再确定可用于切换的停稳阈值。该确认不表示估计器已实现、支持范围/误差已确定或整套环境实现方案均获批准。

拟定组件边界：输入为实际关节反馈、IMU姿态/角速度及主机采样年龄/新鲜度等信息，接触状态由待设计算法估计；输出为明确坐标系下的水平速度向量、时间戳和有效性标志，位置积分可作诊断。[用户确认] 当前整机足部无传感器。[归档/源码核验] 已有position_rad、velocity_rad_s、quat/gyro/gravity及数据质量字段；现行总线IMU输入没有原始加速度，电流物理单位未验证。详细证据见[本机输入核对](../../references/自主训练平台/本机状态估计输入核对.md)。接触估计、主机与传感器时序差异、运动学参数及滤波方式需在第③步补具体方案，不以14维目标动作积分代替实际运动。

验证分两条数据通道：估计器仅读取拟部署可获得的数据；评估器读取仿真真实速度/位置做对照，记录速度误差、响应延迟以及“实际仍在移动却被判停稳”的情况。仿真接触真值如用于诊断，应单独标明理想接触条件，不能作为可部署配置通过的依据。反馈失效或接触不确定时，不得通过填零速度判为停稳；具体失败处理待实现方案定义。

5 cm仍由独立位置测量验收，仿真使用真实位置；未来实物需单独核验测量方式，不能用估计器自己的积分位置证明其自身精度。本机已有归档的数据字段核对完成，未新采集或核验估计精度；下一项为按无足传感器、无原始加速度输入的实际条件形成估计器实现与仿真对照方案，第②步过渡参数仍未全部确定。

## 1. 场景、指令与测量口径

| 项目 | v1 定义 |
|---|---|
| 初态与场景 | 原v1静止入口：当前自建普通足部模型、水平地面，从HOME站姿静止开始。新增移动入口须先经上述减速/停稳交接，不能以HOME静止reset替代；移动入口参数待定。允许踏步换脚，暂不训练摔倒起身、指定角度定位或新的平移行走能力 |
| 坐标与方向 | 世界 Z 向上；由上向下看，逆时针为左转/正值，顺时针为右转/负值；接口与回放必须使用相同定义 |
| 指令 | 用户目标 `yaw_rate_request` ∈ [−30,+30]°/s，0 为停止；内部使用 rad/s（度数乘 π/180），越界或非有限输入拒绝，不静默采用 |
| 指令平滑 | 策略收到 `yaw_rate_command`，以 30°/s² 最大斜率从当前命令向用户目标逼近；从 0 到 30°/s 用 1 s，从 +30 到 −30°/s 用 2 s。请求与实际下发命令分别记录；此机制不等于实际机身运动已平滑 |
| 原地参考点 | `trunk_base`原点的世界XY。静止v1为初始状态锚点；移动入口为停车稳定后、转圈接管前记录的锚点。一旦建立，交接、起转、切换方向和停止均不更新 |
| 漂移 | `d(t)=sqrt((x(t)-x0)^2+(y(t)-y0)^2)`，全过程最大值 ≤0.05 m；启动与停止段也计入，不能用末端误差或低线速度替代 |
| 多圈计数 | 从躯干朝向求 heading，逐步展开 ±π 跳变得到连续 `yaw_unwrapped`；净圈数为连续角差除以 2π。分别报告各方向段，不能只用归一化到一圈的 yaw |
| 实际转速 | 控制采样间连续 heading 差除以仿真时间差；不能把机体系 Z 角速度直接当作偏航角导数。`yaw_rate_measured` 为 0.2 s 因果滑动均值：reset 时窗口为空、前值转速为0，前10个控制步仅平均已存在样本，不填假零；后续滑动10点，变向不清窗口；原始差分值同时保存 |
| 时间与采样 | 全部时长使用仿真时间；控制按现有候选基线 50 Hz。漂移极值、失稳与接触失败应在每个物理子步检查并累计（候选物理步长 0.002 s），控制日志每步保存累计极值与失败标记；不能因日志降采样漏掉越界 |

模型中 `trunk_base`、HOME 高度、控制周期来自现有源码，适用版本必须在运行输入快照中冻结。参考点是躯干原点而非整机质心；更换模型或参考点需要新版本与重新评估。

## 2. 成功与失败判据

除用户指定的 5 cm 外，以下数值为本轮建议默认值。每项均分别判定，不用总奖励替代。

| 检查项 | 判据 |
|---|---|
| 恒速跟踪 | 每次目标变更后前 3 s 为角速度过渡段，之后逐段计算 `yaw_rate_measured` 对用户目标的 RMSE，≤`max(1°/s, 目标绝对值×20%)`。±5/±15/±30°/s 对应 1/3/6°/s |
| 转向与连续性 | 非零稳态段至少 95% 控制样本的转速方向正确；展开角的同向净增量 ≥目标绝对转速×有效时长×80%。在 ±30°/s 的 60 s 稳态段至少 4 圈，±15 至少 2 圈；±5 检查持续低速，60 s 本来不足完整一圈，不硬套多圈门槛 |
| 实际过渡平滑 | 每次启动/变向的前 3 s，平滑后的实测转速对斜率受限命令 RMSE ≤8°/s；该实测转速逐控制步差分的绝对值 ≤120°/s²。两者是运动检查，独立于命令斜率检查；原始瞬时速度另报，不将平滑后合格表述为无高频抖动 |
| 变向响应 | 反向请求发出后 3 s 内，实际转速进入新目标的上述跟踪容差带并连续保持 ≥0.5 s；之后稳态段满足恒速跟踪要求。不能要求用户先发送零速 |
| 停止 | 零速请求发出后 3 s 内达到 `abs(yaw_rate_measured)≤3°/s`，之后连续保持至少 5 s；保持段每个控制样本均满足该条件，期间依然受漂移和站立判据约束 |
| 全程原地 | 每场景所有物理子步的最大漂移 ≤5 cm，含准备/启动、稳态、变向和停止；不允许过渡段豁免 |
| 失稳/接触 | 躯干局部 Z 与世界 Z 的夹角 ≥45°，或躯干原点离地高度 <0.6×HOME 高度，或任意非足部碰撞 geom 接触地面，任一发生即失败。45° 为建议；0.6×HOME 借用现有任务形式，当前 HOME=0.1182 m 得 0.07092 m，均非实物安全界限 |
| 数值/连续运行 | 任一必要输入、观测、动作或姿态出现 NaN/Inf、命令越界、仿真异常或场景结束前发生终止/超时截断/自动重置即失败；不能拼接多个 10 s 回合冒充 60 s 连续转动 |

初始 HOME 必须能作为有效站姿加载；若加载即触发非足接触、失稳或数值异常，应判环境输入不合格并查模型/初态，不放宽行为阈值以掩盖初始化问题。

## 3. 最小评估集

冻结场景表和种子后评估；各场景用种子 0、1、2，分别在 HOME 的关节角上取 ±0.005 rad 均匀初始扰动（限位内），根姿态与根速度保持基线。扰动范围为建议默认，具体初态随运行记录保存。评估不加训练推扰，使用确定性策略输出；这只验当前平地条件，不宣称全速度域或实物鲁棒性已验证。

| 场景 | 时间线与检查 |
|---|---|
| 恒速 ×6 | 用户目标分别为 −30、−15、−5、+5、+15、+30°/s；从 0 开始，共 3 s 启动＋60 s 稳态＝63 s。全过程检查漂移/失败，稳态检查跟踪、方向和累计角 |
| 零速保持 ×1 | 目标为 0，共 3 s 过渡＋60 s 保持；保持段每个样本残余转速 ≤3°/s，全程检查站立与漂移 |
| 变向/停止 ×1 | 同一回合依次为 0（5 s）→+30（15 s）→−30（15 s）→0（8 s）→−30（15 s）→+30（15 s）→0（8 s），总计 81 s；覆盖两种反向和两种方向停止，锚点从最初开始始终固定 |

共 8 场景×3 个初态=24 回合。每个回合都必须通过适用条件，任一个失败则候选未通过；报告各速度、各方向、各初态结果，不能用平均成功率掩盖失败。允许训练中只运行子集作诊断，但报告为部分覆盖，不能标为整体验收通过。

评估器应主动在预定场景终点结束，环境的时间上限应长于该终点；终点前的任何 `terminated`、`truncated` 或 reset 都须判失败并保留失败前数据。所有 60 s 均指有效稳态段，不含 3 s 启动。

## 4. 环境输入与策略接口边界
