# 第④步：训练效果、成本与调参建议

日期：2026-11-06，Asia/Shanghai。响应用户关于训练效果、性价比及环境数/rollout/轮数调整方向的讨论。状态：建议，未实现监控或独立评估器，未改变正式参数，未启动训练。双Spark设备选择已确认，4096×64×1000仍是预算建议。

## 1. 三层评估

**课程更新优先**：用户已决定[先前进、后移动转向](training-curriculum.md)。阶段一建议使用3档直走×3开发种子的9回合切换门槛；下文12回合联合小集属于阶段二候选，不能用阶段一尚未训练的转向得分判定其是否会直走。阶段二保留相同直走回归集。总预算为两阶段合计。

1. 每轮轻量日志：数值有限、终止原因、各族和阶段有效步数、动作raw超界比例、奖励分项，以及库实际可得的KL/损失/动作标准差。按族报告样本分母；每200轮汇总趋势。奖励上涨仅作诊断，不作为达标。
2. 阶段独立评估建议：每100轮保存后冻结模型和观测归一化，使用确定性动作、独立环境、固定开发场景与不同于训练及最终验收的种子。先选12回合小集，例如6个代表场景各2种子，覆盖直走、左右弧线、左右减速接原地转、反向/停止；具体清单需在实现时固化。完整执行每个入选场景的规定时长，不能截取短片段就算60秒转圈成功。训练环境不为评估reset，评估不回写normalizer。最好先做未训练模型的评估基线；如成本过高则减少频率或场景数并标覆盖范围，不缩短判定时长或放宽指标。评估耗时计入成本，分开报告与训练吞吐。
3. 候选正式验收：当开发集表现合适或首轮结束，按acceptance-reference-v2.md的32场景×3种子=96回合执行既定验收；不因开发集全通过而省略。最终验收集不用于反复挑超参，反复使用则需披露选择偏差；通过本仿真参考集不等于真机通过。

同一策略版本、相同初态/场景/种子与归一化条件比较各检查点；回放用于解释问题，不能替代指标。所有阶段同时记录评估成功/尝试数、最差场景、前向/偏航RMSE、跌倒、阶段到达率、停车时间/实际路径、原地最大漂移。提前失败的场景计失败，后续阶段标未到达；不能只用幸存者统计漂移均值。5cm取每回合全过程最大值；训练20cm探索界不能代替5cm验收。

## 2. 性价比的三个坐标

- 样本效率：同样累计新环境转换时，开发评估表现是否更好。epoch复用不重复计作新经验。
- 时间效率：同样包含日志/保存/评估的实际经过时间，表现是否更好；最终以到达同一验收门槛的时间为目标。未达标的运行记为“预算内未达标”，不虚构达标时间。
- 资源成本：节点小时=占用节点数×占用小时（评估使用额外节点时另计）；电耗须积分两台整机功率，现无电表数据，不能由GPU指标或额定功率冒充电费。自有硬件还需考虑第二台占用的机会成本。

[条件推算] 4096规模短测双机/单机吞吐1.6293，如果达到目标所需总样本相同，双机时间约为单机61.4%（省38.6%）；同价节点小时约为单机2/1.6293=1.228倍（多22.8%），不是省成本的证明。当前训练轨迹和分布式统计不同，尚无同目标学习曲线，假设未验证。用户已选双Spark，本分析解释吞吐、时间和成本不是同一指标，不撤销选择。

建议平台同屏展示“累计样本—开发集表现”和“实际分钟—开发集表现”两条曲线，并列节点小时、分项行为指标和最差场景。用Δ成功率/分钟等窗口指标可辅助看边际收益，但小评估集的变化可能是波动，不能作为单一自动停止门。

## 3. 参数调整规则

总并行数N，每环境rollout H，更新轮数I：每轮新样本B=N×H，总样本S=N×H×I；每环境累计推进H×I/50秒（可能包含多次reset）。训练时50Hz与物理步长保持原约定；不能用增大物理dt代替吞吐优化。

| 参数 | 当前建议 | 增大可能适用的证据 | 减小/先查其他项的证据 | 联动项 |
|---|---|---|---|---|
| 并行数N | 全局4096，每卡2048 | 新规模实际吞吐仍增、容量允许且同样本/同时间效果不恶化时，再单独测试8192等候选；不自动扩大 | 同样本评估差、GPU/内存压力或吞吐饱和时，对照2048/1024；相似坏轨迹增多时先查覆盖/奖励/初态 | 总batch、每rank minibatch、总预算、每环境推进长度 |
| 每环境采集H | 64步=1.28秒 | 无中途失败仍有时间关联学习问题时对照128；与critic误差、回报定义及gamma/lambda一并诊断 | 观测到长批次模型更新反应迟缓/学习退步，可对照32；不是仅凭单轮时间决定 | batch、更新次数、存储与实际吞吐，不能假定64→128无成本 |
| 更新轮数I | 上限1000 | 独立评估仍改善、阶段覆盖增加且预算允许时，提出明确新增额度 | 达标候选提前验收；长期停滞/倒退、数值失败或后半段覆盖不足时排查，不能无限加轮 | 累计新样本与节点小时；1000是上限，不是必须跑满的达标要求 |
| minibatch/epochs/LR | 4批/rank、5epoch，沿用短测LR | 需通过实际学习曲线选择，不因大batch自动线性增加LR | 更新退步先查实际KL、裁剪/熵和损失；考虑减小LR或epoch作单项对照 | 5×4=20优化步/轮；raw动作超界率不是PPO概率比裁剪率 |

跨rollout保留物理与任务状态不等于保留整条133秒的精确学习回报：GAE在片段边界使用critic估计，gamma/lambda也影响时间跨度。把H提高到覆盖整个动作并不是必要条件，也不能仅靠更长rollout解决一直跌倒或稀疏奖励。当前网络无记忆，H增大不会自动增加网络观测历史。

## 4. 有限成本的对照顺序

先运行4096×64基线并获得开发评估曲线；每轮轻量监控，从最早阶段就看失败原因，不等200轮才发现错误。200轮作为覆盖/趋势诊断，不把首次低分直接认作方案失败。继续沿用连续两个诊断窗口未到后半段时暂停排查的约束。

仅当出现可定位问题再对照一个配置，预算内先筛选，选中的差异需用额外独立训练种子确认稳定性（多个评估种子不等于多个训练种子）。用于延迟关联问题的有控示例：4096×64与2048×128，每轮都262144样本；保持PPO优化量及总样本相同，改变的是并行广度与连续片段长度，后者每环境推进更久，计算耗时仍需实测。这是联动对照，不谎称只改了一个字段。另选4096×64与2048×64可研究环境数，但同样本下轮数不同，必须记录差异；不能只对比同轮数奖励。

任何改变都生成新配置记录与预算，避免中途静默修改后混合曲线。预定的1000轮为基线预算；额外配置实验属于新增预算，不能自动把每个候选都跑满1000轮。模型选择优先各项硬指标与覆盖，再比较同门槛成本；不靠单一总奖励选择最佳模型。
