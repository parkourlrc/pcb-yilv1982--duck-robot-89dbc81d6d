## 已确认的流程方案 v1

### 输入方式

- 有兼容资产或模板：提供单选、多选或预设选择，展示版本、用途与适用条件；不兼容项说明原因。支持在无适用项时转为自定义，不强制套用错误模板。
- 没有可用选项：提供参考说明、示例、单位、可据来源确定的范围及来源/适用条件，用户填写数值、文本或导入文件。参考值与已采用值区分；缺可靠依据时明确“待补充”，不虚构推荐值。
- 上一步已验证的产物与系统可推导内容：自动带入，显示来源与版本，用户无需重复填写。覆盖会形成新的输入版本。
- 本轮将“用参考”理解为带参考的填写或导入；不是把参考数值静默视作本机实测或自动采用。

### 每步的执行与验证

每一步采用：输入选择/参考填写 → 输入验证 → 执行 → 输出验证 → 合格产物进入下一步。

- 输入验证包含完整性、类型/单位/范围、版本与接口兼容性，以及当前任务约束；输出验证包含产物完整性、与本次输入的对应关系及本阶段质量要求。
- 输出要求在执行前展示；训练完成仅意味着生成了符合约定的候选产物，策略是否达到行为目标由评估步骤判断。
- 结果显示通过、未通过、待验证、不适用；必要的人工判断注明操作者、时间和证据，不能由文件存在或程序退出成功替代。
- 必须通过的检查未通过或尚待验证时，不把本步骤标为完成、不把产物标为合格。允许保存草稿、查看诊断和重试；提示具体字段、期望条件、实际结果与修正入口。
- 上游输入改变后，将受影响的下游结果标为“需重新验证”；保留旧版本及记录，未受影响的结果不重复验证。
- 每次验证绑定输入版本、输出版本、规则版本、结果、时间与证据；检查规则变化时不继续沿用旧的通过状态。
- 本轮用户明确要求逐步验证；实现时采用足以检查当前要求的最小验证集，复用已有结果，不扩展为无关自检。

### 步骤开始与完成的表达规则（2026-11-05 补充）

固定编号：①策略需求 → ②任务定义与验收标准 → ③训练环境组装 → ④训练方案 → ⑤执行训练 → ⑥独立评估与回放 → ⑦策略交付；需要实物时扩展⑧部署验证 → ⑨数据回灌。保持编号稳定，不把代码实现的子任务或项目 Spec 五阶段混作训练步骤。

- 开始时明确写“开始第 N 步｜步骤名称”，说明本步做什么、为什么需要它、使用哪些已验证输入，以及预期产物与通过条件。随后才开展该步骤工作。
- 完成时明确写“完成第 N 步｜步骤名称”，简述本步做了什么、产物对后续的作用、实际产物位置、输入与输出检查结果，再说明下一步是什么及是否已经开始。
- 若只产出文档或方案，必须明确“文档完成/方案完成”；未完成实现和运行验证时不能把整个环境组装或训练阶段标为完成。
- 有必需项待验证、待确认或失败时，使用“第 N 步进行中／待确认／未通过”，说明剩余项与下一动作；不能仅因结束当前聊天轮次就宣告完成。
- 同一轮推进多步时，先报告上一步完成及检查结果，再报告下一步开始。尚未执行的步骤只称“下一步”，不能提前称“已开始”。
- 跨轮继续时简述当前步骤和进度；发生返工时写“返回第 N 步”，说明原因及受影响产物。开始/完成通知用于表达进展，不额外增加对已授权操作的确认要求。
- 所有通知区分用户确认、参考默认、文档检查与实际运行结果。流程本身的维护标为“流程规范更新”，不增加或挤占策略训练步骤编号。

表达模板：

> **开始第 N 步｜名称**：本步做……，作用是……；输入为……，将产出……，按……验证。
>
> **完成第 N 步｜名称（完成范围）**：已完成……，供后续……使用；产物……；输入检查……，输出检查……，尚未验证……。下一步为第 N+1 步……（尚未开始/随后开始）。

### 阶段矩阵

| 阶段 | 可选择的输入 | 无选项时提供的参考 | 输入验证 | 输出验证 |
|---|---|---|---|---|
| 策略需求 | 能力模板、机器人版本、场景、交付目标 | 需求示例、能力描述与约束填写说明 | 必填项齐全、目标与所选对象无明显冲突 | 需求可转为任务与可判定指标，未决项显式列出 |
| 任务定义 | 命令、初始化、指标、成功/失败规则模板 | 阈值、时限、接触条件的示例及依据 | 指标单位/范围一致，规则无逻辑冲突 | 任务说明完整，每项需求有对应验收条件 |
| 环境组装 | 机器人/场景、观测/动作、奖励/重置/终止组件 | 自定义参数说明、组件接口、导入示例 | 资产存在、接口语义/维数/单位/关节映射相容 | 环境可加载和执行必要的最短步进，输出结构及数值有效 |
| 训练方案 | 算法、网络、课程、随机化与资源预设 | 超参数和预算参考、适用条件 | 算法/网络与环境接口匹配，参数及预算有效 | 完整训练配置可解析、版本引用明确，形成可执行任务 |
| 执行训练 | 计算资源、新训/续训、兼容检查点 | 启动配置与资源估算依据 | 所需资源/依赖可用，续训状态与配置兼容 | 检查点可加载、关键数值有效、日志与实际配置齐全；单独标明完成或中断 |
| 独立评估 | 候选模型、评估场景、指标组合 | 新场景与判定阈值填写示例 | 模型/预处理/环境契约一致，评估条件与需求对应 | 按预设指标判断，报告包含失败场景与覆盖范围，不以训练奖励代替验收 |
| 策略交付 | 已评估候选、导出格式、运行端 | 自定义运行端接口与打包模板 | 评估状态、格式和目标运行端兼容性满足要求 | 导出包完整可加载，代表性输入下导出前后推理结果符合事先约定的容差 |
| 部署验证（扩展） | 目标设备、标定版本、运行配置 | 动作验证与记录模板 | 设备、标定、接口与运行前提匹配 | 根据实物证据判定动作与停止要求；文件加载不替代动作验收 |
| 数据回灌（扩展） | 日志、运行版本、问题类型 | 失败标注、参数修订说明模板 | 来源、时间戳、字段与关联版本完整可解释 | 形成可追溯的问题记录或修订建议；证据不足保留待确认 |

上述为行为要求，不在本轮决定前端框架、API、持久化 schema 或具体阈值。

## 验收场景

1. 有兼容模板时可选择并显示来源版本；没有适用模板时有参考与填写/导入入口；参考不被默认标为实测。
2. 必填缺失、单位错误、接口不匹配时，定位到对应输入项；草稿可保存，依赖执行不可被标记为通过。
3. 执行成功但输出缺失、不可加载或不满足本阶段要求时，仍判未通过；训练候选未通过行为评估时不能成为已验收交付物。
4. 人工验证尚未完成时显示待验证；完成后记录人员、时间和证据。
5. 改动机器人、任务或接口版本后，受影响下游标记需重新验证；历史结果可追溯。
6. 每步可查看输入、输出、通过条件、实际结果、证据与修正入口；无需重复输入上一步产物。
