# 第⑤步训练可视化工具：修改方案

- 日期：2026-11-06（Asia/Shanghai）。
- 状态：用户已批准本修改方案，2026-11-06进入编码；按runtime、backend、frontend分片实现并独立审查。实际验证与未完成项见[实施记录](implementation-record.md)。
- 基线：[已确认需求](spec.md)、[文档核对](document-confirmation.md)、[Studio模型来源](studio-model-source.md)。
- 目标：交付可启动训练、查看真实过程、选择checkpoint并用Studio模型多窗口回放的本地网页工具。

## 1. 使用方式与页面

Windows运行一个PowerShell启动脚本，打开本机网页，默认端口8765。网页服务管理任务与运行；训练在选定的本地WSL GPU或Spark执行。浏览器刷新/关闭不结束训练，重新打开可接回运行。

### 页面布局

左侧固定任务及历史运行导航；顶部显示任务版本、运行名称、计算环境、阶段与启动/停止操作。主区域分四个页签：

| 页签 | 内容与交互 |
|---|---|
| 训练概览 | 当前轮/目标轮、累计转换数、耗时、ETA、吞吐与最新checkpoint；奖励/episode length/开发通过率主图，下方展开loss、entropy、std、lr、动作裁剪等诊断；底部为事件/错误日志。 |
| 检查点与回放 | 左侧按轮次筛选checkpoint，显示保存/完整性/评估状态；右侧单窗、双窗、四宫格，窗口有checkpoint身份、播放/暂停/重置/倍率/视角；窗口下方是对应指标与命令/实际速度、角速度、姿态、轨迹曲线。支持单独打开浏览器窗口。 |
| 计算资源 | 本地、spark1、spark2各自卡片及时间曲线，显示运行占用和采集时间；CPU、内存、GPU利用率、设备内存、温度/功耗及磁盘/网络吞吐，区分不支持与失联。 |
| 配置与记录 | 查看不可变的本次配置、来源/依赖版本、任务说明、参数、预算、恢复来源及输出路径；新运行配置用侧边面板编辑。 |

视觉：深蓝黑背景、分层面板、青蓝重点色，绿色正常、黄色等待/过期、红色失败；图表轴/单位清晰，无数据时显示原因。默认概览优先展示训练效果，诊断和长日志按需展开。窄屏回放改为纵向排列，不缩成不可读四宫格。

### 新运行参数面板

- 任务及版本：从已建立任务列表选择，不在此编辑物理模型、奖励或算法。
- 计算环境：本地GPU / 单Spark（选择spark1或spark2）/ 双Spark。
- 全局环境数N、每环境每轮采样步数S、最大更新轮数U、保存间隔C、开发评估间隔E、随机种子。
- 即时显示每节点环境数、每轮N×S转换、总预算N×S×U；双Spark每节点N/2，必须正偶数，并检查每rank批量可被任务mini-batch数整除。
- 默认值读任务配置，不写死通用4096/64/1000。参数提交后先返回解析后的实际配置与校验结果，页面按该结果启动。
- 首版每次仅一个活动训练作业，可同时有2至4个回放会话；保留多个任务/历史运行，不实现训练队列或自动超参搜索。已有外部训练只读导入，不自动接管停止。

## 2. 技术组成与进程边界

采用Python FastAPI控制服务、Preact/htm页面、ECharts学习/负载图表、three.js Studio模型显示。前端依赖固定版本并放本地，不依赖运行时CDN；优先复用Studio固定版本的Preact/three.js及许可，ECharts补充固定分发版。控制服务使用独立依赖环境，不升级训练环境的torch/mjlab。

控制服务运行在Windows，提供同源静态页面、REST和WebSocket；调用本地WSL/远端SSH的执行适配器。服务默认仅绑定127.0.0.1，写操作及WebSocket检查本机会话和Origin。前端提交结构化字段，不接受任意shell命令。

各训练节点有本工具工作目录和轻量运行监督进程，启动/停止/状态/日志传输通过SSH或wsl.exe访问。控制面不导入torch，不占用GPU；训练、回放、资源采集分别有独立进程与状态，不能让网页连接持有训练生命周期。

SQLite只存任务索引、运行/节点/回放身份、连接游标和界面状态。原始运行JSONL、checkpoint、预算账本仍是事实依据；数据库缺失可从运行元数据重建，不从数据库重算或返还训练预算。

## 3. 任务接入与版本固定

新增training/tasks/中的任务描述，至少包含：

| 字段 | 用途 |
|---|---|
| schema、task_id、task_version、title、description | 任务身份、显示名称与说明。 |
| adapter_id、runtime_version | 指向本项目登记的训练/回放适配器，不允许描述文件执行任意脚本。 |
| source_files、source_hashes、physics_model、observation_action_contract | 绑定前序产物，检验文件和接口来源。 |
| default_execution、editable_execution、constraints | 默认执行参数、允许改动字段、整除/兼容约束。 |
| evaluation_suites、metrics、display_model_version | 场景、任务效果指标与Studio显示资产版本。 |

首个接入现有前进/减速/转向联合任务。增加任务可通过另一份已就绪描述和已注册适配器实现；任务列表不硬编码到前端。任务缺失依赖显示具体缺项，历史任务可查看记录但不冒充可执行。

每次新运行在独立目录冻结训练配置、任务描述、实际运行源码/模型/参数和依赖版本清单。冻结包含mjlab_duck包及实际导入文件，不能只复制顶层脚本。相同运行的双节点源码哈希一致；已有文件不被新的运行覆盖。

## 4. 本地、单Spark、双Spark执行

| 模式 | 启动与环境分配 |
|---|---|
| 本地GPU | 使用已配置的WSL发行版和训练venv，单进程CUDA，world_size=1，环境数N。Windows只负责控制和浏览器。 |
| 单Spark | 在所选节点独立目录启动一个训练容器/进程，world_size=1，环境数N，复用该节点已验证依赖。 |
| 双Spark | spark1为rank0、spark2为rank1，各一进程、各N/2环境；torchrun双节点，独立运行名/会合标识/端口，沿用既有通信环境。 |

节点配置记录实际SSH目标、工作根、解释器/容器配置和GPU选择；不根据历史路径假定环境仍存在。启动前仅检查本次运行必要的文件、解释器、目标设备、通信可达及空间；不重复长测速。

双机启动先准备两端目录和相同输入，再发起启动；一侧准备失败不得只启动另一侧。启动中一侧退出时停止该作业的对端，保存两端错误和退出状态。监督进程保留自己的PID/启动时间或容器ID，不按模糊进程名停止其他作业。SSH暂断标为失联、继续尝试恢复观察，不自动重启训练或消耗新预算。

新运行执行目录与原正式实验目录隔离。以参数形式传入配置；扩展训练main和train_loop，使正式运行支持world_size=1或2，保留整除检查和真实评估；检查模式仍独立。

## 5. 保存、评估、停止与恢复

### 独立调度

训练配置新增eval_interval，默认等于既有save_interval以保持原默认节奏。保存按C执行，开发评估按E执行。评估点即使不是计划保存点，也先保存可追溯候选，再把报告绑定该checkpoint；评估后保存课程门控状态。C/E重合时共用评估前候选，避免重复写同一状态。

课程“连续相邻评估通过”改为依据E判定；奖励、采样概率、场景、阈值和既有阶段切换语义不变。额外手动回放不推动课程。末轮和停止均保存最终完整checkpoint，标明是否已有评估。

### 运行状态与停止

持久状态包括准备、初始化、训练、评估、保存、停止中、正常结束、已停止、失败；另有连接正常/过期/失联状态。连接状态不能覆盖任务实际状态。非零退出和错误应可定位到节点/rank。

停止通过本工具run_id投递请求，由训练在更新边界协调处理并保存；可以等待当前评估结束，UI显示“停止中，等待评估完成”。异常退出保留最后完整checkpoint，不承诺保存未完成更新。双机必须看到两rank终态及完整manifest才显示停止完成。

### 恢复兼容

- 继续使用原experiment与预算账本，新建run段记录parent_checkpoint。model_iteration与预算消费量分别显示，回退旧checkpoint不会返还消费额度。
- 完整续训要求原任务/代码版本、配置、world size兼容；续训界面锁定这些参数。预算耗尽明确显示不能继续，不隐式加轮数。
- 新训资源可自由选择，但双机改单机等拓扑迁移不属于完整恢复；首版明确说明不兼容，不自动抽rank0伪装恢复。纯actor推理回放单独处理。
- 在修改训练合同相关源码前，保存并校验现有v1运行源快照；旧checkpoint通过对应冻结版本适配器读取，不能删掉哈希检查让新代码强行接旧模型。旧数据只读保留。
- v1源码可从原运行sources取得并核对合同哈希；若某历史运行缺少必要文件或依赖，标“缺少兼容运行时”，保留已知曲线/评估，不能宣称可恢复。当前首轮已耗尽预算，工具不会因加载它而自动重训。

## 7. Studio模型与多窗口回放

保留software/studio/model-source-2026103101/作为原件；新网页使用可写适配模块读取其model.json与meshes.bin，保持原几何、材质和模型版本。

[源码核验补充] 原duck3d.js的setGravity只给俯仰/横滚，注释明确偏航为0，原视图还对根位置做居中；直接原样套用会看不到完整转向/平移。因此新回放适配使用仿真世界根位置及完整四元数驱动模型，调整居中/随动相机逻辑；不能从重力反推yaw，不能复用硬件标定方向。

### 回放数据与控制

- 回放使用独立进程加载冻结actor及归一化，默认确定性输出；按task_version/adapter构建单环境仿真，选择任务提供的场景和seed。
- checkpoint来自双rank时默认rank0用于推理，显示rank身份；推理加载不要求为它启动双机训练。对旧v1同样核验来源并使用匹配运行时。
- 发送world position、wxyz quaternion、按名称标识的关节角、仿真时间、命令/实际速度/角速度、姿态与事件。数据带replay_id和seq，独立窗口不得串流。
- Studio额外mouth显示关节在任务无动作时固定默认，不新增训练动作；关节名称/轴/零位与根变换须用当前模型实际核对，不套舵机ID。
- 每窗独立暂停/继续/重置、0.5×/1×/2×、视角与相机跟随；控制物理步长不因倍率变化。重置恢复相同场景seed与策略冻结状态。
- 至少支持两路，提供四宫格；默认回放计算在本地WSL GPU，前端呈现其资源位置。本地训练时两者共享GPU，显示占用并允许关闭回放；不会自动切到远端或削减训练环境数。
- WebSocket姿态流目标20–30Hz，页面可做纯显示插值；物理/指标使用真实控制采样。慢页面丢弃过时画面、保留最新姿态，不积压仿真命令。倍率和实际仿真实时率分别显示，不承诺四窗满帧。
- 关闭窗口释放会话资源；独立浏览器窗口可重新连接原会话，不能因刷新再启动重复GPU进程。进程崩溃保留错误及已有回放指标。

显示源快照含16个body/28个mesh，实际采用当前Studio来源，不用原MuJoCo简模顶替。地面、轨迹和坐标辅助可以新建；显示层不参与碰撞或改变训练物理。

## 8. 资源采集与刷新

每2秒采集一次节点负载，与当前run关联且保留原始时间。CPU/内存/磁盘/网络由平台采集器提供；GPU优先NVML，必要时使用有超时限制的nvidia-smi只读查询。各字段声明单位、作用域和支持情况。

本地CPU/系统内存展示Windows主机统计，同时标明训练在WSL；WSL侧进程/内存单列，不能把VM内存当整机内存。Spark采集宿主机统计，不以容器局部值冒充整机。统一内存与独立显存按设备实际报告区分，不把同一内存重复相加。

图表显示每节点的CPU%、内存used/available、GPU%、设备内存、温度、功耗、磁盘/网卡吞吐；全节点值不声称由训练独占。进程级GPU内存不可得时标不支持。带宽按实际时间差计算，首次采样为空；采集失败显示过期，不写0伪造空载。

## 9. API与持久数据

| 接口组 | 主要操作 |
|---|---|
| /api/tasks、/api/resources | 可执行任务/版本、资源配置及状态，刷新必要探测。 |
| /api/runs/validate、POST /api/runs | 校验配置与预算，创建运行；启动请求带幂等request_id，重复点击返回同一run。 |
| /api/runs/{id}、/stop、/resume | 状态、停止、兼容续训；停止也是幂等，恢复返回新run段与原experiment关联。 |
| /api/runs/{id}/metrics、/events、/checkpoints | 历史曲线分页/降采样、事件、checkpoint列表与评估关联；不只靠文件名猜轮次。 |
| POST /api/replays、/api/replays/{id}/control、DELETE | 创建、控制、释放回放会话；只允许已登记来源和完整文件。 |
| /ws | 订阅run/resource/replay事件，包含seq和游标；REST拉取初始快照及断线补齐，回放帧可丢弃但运行事件持久保存。 |

运行目录记录run.json、config/task快照、events/updates/episodes/resources、evaluation报告、checkpoints、result/failure和原始进程日志。远端仍为原件位置，本地缓存采用长度/哈希确认和临时文件原子替换；未完成下载不能显示“可回放”。完整恢复保留各rank文件；推理可以只缓存manifest指向的所选rank及其来源，不能因此标为完整可恢复。

旧运行采用只读登记来源路径；导入是索引和必要缓存，不移动/删除原产物。设备账号、主机地址、解释器和工作根放本地配置；仓库只提交脱敏示例。源码/模型原件与运行大文件分开管理。

## 11. 实施顺序与必要验证

1. 固定现有训练v1来源并核对旧checkpoint合同；建立任务描述、运行目录、配置校验与历史日志索引。

## 12. 风险、回退与未完成边界

- 旧checkpoint绑定源码哈希：先保留v1冻结来源，用版本适配解决，不删除检查。新版本运行互相独立，回退用旧入口/原记录；不能保证新checkpoint可被旧代码加载。
- 多窗口与训练共享GPU：有实际资源显示与独立关闭，性能不足时明确实际速度；不通过降低训练物理精度或改模型掩盖。
- Studio根变换与训练骨架存在差异：检查零位/代表关节和root pose，适配的是显示映射，任何必须改变训练物理的发现另行讨论。
- 远端目录/依赖以现场为准；未知路径不写入可执行默认。节点不通不阻塞本地UI/历史数据/回放设计。
- 取消工具可关闭其控制服务与回放进程；活动训练由监督进程继续登记，需明确停止该作业才结束。原机器人服务与已有实验不受改动。
