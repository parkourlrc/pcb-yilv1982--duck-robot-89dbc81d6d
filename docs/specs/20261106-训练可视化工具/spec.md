## 1. 用户原始需求与范围

建设网页工具，仅覆盖既定流程的第⑤步“执行训练”：选择前序已建立的训练任务，调整训练执行通用参数，选择 checkpoint 并多窗口回放，以 RL 图表展示 checkpoint 效果、实时训练进展与训练效果，以及训练计算环境负载。界面采用科技风、暗色调。

[用户最终指定，2026-11-06] 训练回放使用当前主控Studio实际加载的3D显示模型，不能以MuJoCo胶囊/盒等简模作为回放外观。本决定替代此前“定位实际打印文件”的来源条件，不再要求用户提供打印包。具体资源版本及读取状态见[Studio模型来源记录](studio-model-source.md)。

当前按已批准方案编码与验收，训练严格限制在方案明确的小预算范围。第⑤步允许在训练过程中预览 checkpoint 和读取已有开发评估；这些结果不自动完成第⑥步独立评估。任务定义、奖励、物理模型、观测动作接口、网络及课程设计沿用前序产物，编辑这些内容不列入本工具首版范围。策略导出、部署和真机控制不在本次范围。

## 2. 已确认功能与验收要求

| 功能 | 行为与验收要求 |
|---|---|
| 任务选择 | 选择前序建立且可执行的任务版本；显示任务名称、说明、环境/训练配置版本及准备状态；运行记录归属于任务。首个接入实例为已有前进、减速与转向联合策略，保留后续任务接入能力，不能将该任务写死成唯一页面。 |
| 执行参数 | 调整最大更新轮数、每环境每轮采样步数、checkpoint 保存间隔；同时提供全局并行环境数、随机种子、开发评估间隔及计算资源选择。默认值来自所选任务，修改后显示实际生效值及预算变化。 |
| 计算环境（用户确认） | 首版可选择本地 GPU、单 Spark、双 Spark；单 Spark 可选择具体节点。填写全局环境总数，双 Spark 各分配一半，页面显示每个节点的实际环境数。 |
| 训练控制 | 提供启动新运行、安全停止并保留完整检查点、从兼容 checkpoint 续训；显示初始化、训练、评估、保存、已结束、停止中、已停止、失败/失联等状态。刷新网页后可重新接入同一运行，不能重复启动。 |
| checkpoint 列表 | 按运行列出轮次、累计采样量、生成时间、课程阶段、文件完整性和已有评估结果；可选中历史或最新完整 checkpoint，不加载仍在写入的半成品。 |
| 多窗口回放 | 同时回放不同 checkpoint，或同一 checkpoint 的不同场景；首版支持至少 2 路并排、目标 4 路，提供独立播放/暂停/重置、速度与视角控制，并可单独打开窗口。每个窗口显示任务版本、运行及 checkpoint 身份。 |
| Studio模型显示（用户明确指定） | 所有回放窗口复用当前主控Studio实际加载的3D外观，按所选checkpoint的仿真关节运动；读取并固定显示几何、材质、层级及挂接信息，记录资源来源/版本/哈希。不得以胶囊/盒简模或未核对的其他资产替代；模型缺失或加载失败时显示具体问题，不静默回退为简模。 |
| checkpoint 效果 | 显示其训练时刻的指标、对应已有开发评估结果，以及本次回放的时间曲线；无对应评估时明确“未评估”，不能拿附近轮次或其他窗口的数据冒充。回放场景、命令和 seed 可见，对比须标明条件差异。 |
| 实时训练图表 | 每轮指标生成后增量更新，展示总轮数/当前轮、累计采样量、耗时、吞吐、预计剩余时间；以曲线展示学习指标与开发评估变化。初始化、评估和保存期间也有状态心跳；断连显示数据时间与过期状态。 |
| 环境负载 | 按实际执行训练的节点分别显示 CPU、内存、GPU 利用率、GPU/统一内存、温度、功耗及磁盘/网络吞吐的时间曲线；不可采集项显示“不支持/无数据”。同时显示回放运行在哪个节点，区分节点总负载和可取得的进程负载。 |
| 网页界面 | 简体中文、深色背景、清晰的青蓝重点色与状态色；任务/运行导航、训练概览、参数、图表、checkpoint 与回放、资源监控可直接到达。科技感不以牺牲图表可读性为代价。 |

### 参数和预算口径

- “一轮”统一指一次 PPO 更新迭代，区别于 episode 和内部优化 epoch。
- “一轮多少步”指每个环境的 rollout 采样步数；页面同时显示每轮全局转换数 = 全局环境数 × 每环境采样步数，最大新训转换数 = 更新轮数 × 每轮全局转换数。
- 多节点环境数按全局总数计算，不再次乘节点数。episode 长度沿用任务定义。
- [用户确认，2026-11-06] 首版同时支持本地 GPU、单 Spark、双 Spark，双 Spark 平均分配环境数。[由均分要求导出的校验] 双 Spark 的全局环境数必须为正偶数且至少为 2；每节点环境数为全局总数的一半。奇数输入提示修正，不静默取整或改变总量。本地 GPU、单 Spark 各承担全部环境。
- 例：全局 4096 环境在本地 GPU或单 Spark 模式为单节点 4096，在双 Spark 模式为 spark1 2048＋spark2 2048。rollout 为 64 时，三种模式每轮均为 262144 个转换；切换计算环境不自动翻倍总训练预算。示例不构成任何设备容量或实时可用性的保证。
- 参数在启动前编辑并形成运行快照；首版不要求运行中热改参数。续训参数受完整恢复合同约束，不能把不兼容配置静默当作原运行恢复，也不能清零已消费预算。
- checkpoint保存间隔和开发评估间隔独立配置，实现见[方案第5节](implementation-plan.md)及[运行时记录](runtime-implementation.md)：新增eval_interval，评估点独立绑定候选checkpoint，课程连续通过按评估间隔判定；正在核验实际执行路径。

### 回放显示与训练物理边界

- 使用当前主控Studio模型形成可随关节运动的整机显示，保持其几何、材质、比例和装配外观。若需转换显示格式，保留原始资产和转换记录，不用重新画的近似壳体替代。
- 显示网格挂接到所选任务的仿真骨架；本需求不自动改变训练碰撞、质量/惯量、关节或观测/动作接口，也不表示已经完成实物动力学对齐。
- [文件核验] 已按部署固定提交恢复[Studio模型与加载源码](../../../software/studio/model-source-2026103101/README.md)，六个文件Git blob哈希与来源树匹配。本地servo-web网格同哈希，Studio的JSON有两个额外servo_joint标记，采用完整Studio版。实际打印CAD一致性不作为本工具前置，也不声称物理已对齐。
- [来源可用] Studio模型、材质、装配/关节数据和加载入口已在本地保存，设备离线不阻塞后续设计。当前板侧文件尚未重新比对，有无部署后的额外改动保留为待核验项，详见来源记录。
- 验收须能追溯到主控Studio实际使用的资源，并检查各窗口的模型、比例、材质、零件位置及关节运动。原件、显示工作副本和来源清单存放于本项目可写目录，不修改板侧资源或只读参考库。

### 图表要求

1. 学习效果：平均 episode return、episode length、奖励分项、任务成功/失败率；区分每步奖励均值与完整 episode return。
2. PPO 诊断：policy/surrogate loss、value loss、entropy、learning rate、action std、动作裁剪比例；KL 等字段须有真实采集来源后展示。
3. 开发评估：通过率、速度/角速度跟踪误差和任务提供的行为指标，标记 checkpoint 与课程阶段；训练奖励不替代行为达标。
4. 回放效果：命令与实际速度/角速度、姿态、轨迹及失败事件；时间轴为本次回放时间，和训练迭代轴分开。
5. 训练效率与资源：采集/优化耗时、全局 transitions/s、节点利用率与内存/温度/功耗等时序。
6. 训练曲线支持按迭代、累计转换数或实际耗时查看（字段可用时），提供原始值与可调平滑，保留单位、采样周期和数据来源；rank0 指标不能标为全局均值，缺测不补零，不用演示数据冒充实时值。

上述是拟实现指标，不代表旧日志已经全部具备。完成率、失败率须注明分母与统计窗口；开发评估是稀疏采样点，不伪造成逐轮测量。ETA 按已测吞吐及开销估算，数据不足时显示“估算中”。
