## 需求复述与建议视觉方向

采用深海军蓝背景与蓝灰面板，青色为唯一主要交互强调色，少量紫色作为图表第二序列或局部辅助标记；正文保持冷白与浅蓝灰。霓虹只落在当前选中项、关键进度和焦点反馈，避免整块卡片发光。大面积使用深色底和面板，彩色面积建议控制在约5%以内，作为设计方向而非机械像素门槛。

| 用途 | 建议颜色 |
|---|---|
| 页面底色 | `#080F1D` |
| 卡片面板 / 抬升面板 | `#101C2E` / `#17263B` |
| 边框 | `#283C54` |
| 正文 / 次级文字 | `#E7F0FA` / `#9BAEC5` |
| 主强调：冰青 | `#37DDE8` |
| 辅助强调：电紫 | `#A394F5` |
| 成功 / 警告 / 失败 | `#57D9AB` / `#F2C46D` / `#FF7895` |

- 主操作和选中项突出，成功/警告/失败可区分，曲线在深色背景上清晰；禁用态与可操作态可辨。
- 桌面及窄屏不因配色修改产生布局变化；检查已有数据展示即可，不启动训练。

### 文件与实现范围

1. `training/dashboard/web/styles.css`：统一主题变量，移除末尾黑白灰主题覆盖，按语义替换组件写死的颜色；保持现有选择器行为、尺寸、间距与响应式断点。背景采用深海军蓝，卡片采用蓝灰，边框低饱和；文字统一冷白/浅蓝灰，次级文字以可读性为先。表单焦点、当前标签和选中记录使用冰青细边/细线；仅这些局部和进度条保留低强度静态光晕。普通卡片无发光。
2. 主按钮采用冰青底、深蓝文字；次按钮为蓝灰底、浅色文字，悬停仅加深层次或提亮边框。正在运行使用冰青，成功使用薄荷绿，暂停/等待/过期使用琥珀，失败/错误使用柔红；保留原状态名称与文字，预算结束不改写成行为通过。电紫限于图表第二序列及少量辅助标记，不给每张卡片添加彩色框。
3. `training/dashboard/web/charts.js`：曲线颜色为冰青、电紫、蓝、薄荷、琥珀、柔红；后四种仅在多序列需要时使用，不制造额外装饰。增加CSS图表色变量并在既有图表更新处读取，统一图例、提示框、坐标轴和网格颜色。保留现有实线/虚线/点线区分、数据过滤、平滑、单位、缩放与采样口径。
4. `training/dashboard/web/index.html`：页面图标调整为深蓝底冰青线，样式资源更新版本标识以便加载；不增加外部字体、依赖、图片或网络请求。JS模块通过浏览器重新加载确认新颜色，不为纯配色修改应用逻辑。
5. 3D机器人材质、灯光与场景网格保持现状；回放外围面板、控件及背景容器随CSS主题统一。`studio-model.js`、`app.js`、训练任务清单和后端不在计划改动范围。

### 必要检查

- 普通正文、次级文字、表单文字及各状态文字与实际底色对比度至少4.5:1；焦点/关键交互边界目标至少3:1，禁用控件单独检查辨识度。若候选色在实际叠层底色上不达标，只在同色系内调整亮度并记录实际值。
- 查看桌面宽屏与窄屏下的首页/曲线、档案、参数抽屉、资源页以及回放周边；检查是否有漏改灰色、溢出、低对比度、过量发光。只读浏览和开关表单，不提交训练或续训请求；回放若无现存会话则只核对外围组件，不为验配色启动GPU回放。
- 修改过的JS做语法检查，检查静态资源响应、浏览器报错及`git diff --check`；核对差异仅为显示样式、图表主题读取和文档。无需重跑后端测试、训练或GPU短跑。
- 浏览器工具若不可用，记录实际限制，不将HTTP成功或截图文件存在当视觉验收；不绕过工具限制。
